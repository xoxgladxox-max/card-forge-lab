# 分诊与调度细则

适用场景：第 0 步需求分诊遇到边界情形或信息半全时读取本文件。

> 分诊前先写出明确判断：角色来自已知作品还是原创构思（决定走填充路径还是引导路径）、在整张卡里承担多少戏份（决定 `mini` / `standard` / `full` 档位）、哪些归本我内核硬锚点、哪些留作可能性空间采样。

## 分诊问题清单

用户尚未交代清楚的维度，在第 0 步的那一次提问里一并问齐：

### 维度 1：资料基础 → 决定路径

问法：「这个角色来自现有作品（动画 / 小说 / 游戏 / 漫画），还是原创角色？」

| 用户信号 | 路径落点 |
|---|---|
| 给出作品名与角色名 / 贴出设定词条 / 提供完整原稿 | 多料 → **填充路径**（基于考据材料提炼本我内核与语料采样） |
| 给出初步人设方向 / 概念草图 / 原创 OC | 少料 → **引导路径**（分步补齐核心设定与互动张力） |
| 已有部分设定碎片，局部细节留白 | 半全资料 → 见下方边界处理 |

- 涉及现有作品角色时先走调研备料，用两源以上一手与百科材料交叉核实设定与原话台词。

### 维度 2：角色戏份 → 决定起步档位

问法：「这个角色在故事里承担什么戏份？阶段配角、长期同伴，还是核心主角？」

| 用户信号 | 起步档位 | 关注重心 |
|---|---|---|
| 群像配角 / 阶段登场人物 / 快速验证 | **mini** | 精简身份、2～3 处视觉锚点、核心动机与代表台词 |
| 主力角色 / 长期同伴 / 核心对手（常规默认） | **standard** | 完整本我内核（认知功能、执念、底线）+ 分场景可能性采样 |
| 独占长线主角 / 多阶段关系演化 / 高还原复刻 | **full** | 深度心理因果、多层次关系演化、专项特化模块与丰富声纹库 |

- 档位由实际戏份与互动深度决定；字段密度与升降档衔接遵循 `cf-card-character/SKILL.md` 的选档规范。

### 维度 3：推进节奏模式

在第 0 步出卡单中确认：

| 模式 | 停顿节奏 | 适用情形 |
|---|---|---|
| 分模块精修模式（默认推荐） | 每完成 1 个独立文体模块停下交付 | 注重文体纯粹度、逐块把关细节与反套路质感 |
| 全自动直通模式 | 第 0 步确认出卡单后直通至成品交付 | 快速出样，待决项统一标【提案】/【缺口】汇总审阅 |

## 边界情况处理

### 1. 半全资料（局部有设定、局部留白）

- 以填充路径起步，先盘点现有材料覆盖的本我硬锚点，列出缺失项。
- 区分两类缺失信息分别处理：**可检索的客观设定**（出身、身高、阵营、事件经过）交调研分包补查；**主观体验取向**（对 `{{user}}` 的初始关系定位、尺度边界、分支走向）列入出卡单请作者拍板。

### 2. 基于已有卡修改与升降档

| 情形 | 处理方式 |
|---|---|
| 升档（`mini → standard → full`） | 保持原有字段路径稳定，向下补充心理机制、关系层次与情境采样 |
| 降档或超长卡精简 | 按「跨层去重 → 剥离通用规则回世界书 → 合并同类项 → 精简重复采样」顺序收敛密度 |
| 局部修订（补台词 / 调性格 / 改关系） | 先定位最高出错层，聚焦目标模块修订，完成后执行对应审查项与 `[P25]` 核查 |
| 旧卡缺少关系边界或本我/可能性分层 | 对照现行角色模板补齐 `boundaries` 与 `roleplay_tips` 自由派生声明 |
| 旧卡静态设定混入单轮动态心情或玩家状态 | 将静态人物内核保留在角色节点，动态局势与开局穿戴移交开场白与 `<status>` |

### 3. 多语种输出需求

- 沿用统一的节点目录结构与标签体系，将字段内容按目标语种撰写。
- 角色原话台词优先保留最具辨识度的原文自称、口癖与句尾助词，或在双语对照中标明原声特征。

### 4. 酒馆（SillyTavern）槽位分工

各字段的装配去向以 `cf-card-format-export` 的槽位规范为准：

- `description.md` 承担纯泛用上位总控（角色定位、肩扛镜头边界、GM 响应规则、输出结构），保持常驻零绿灯词泄漏。
- 角色具体设定、配角档案与台词语料放入 `lorebooks/character/` 世界书条目。
- `personality` 与 `scenario` 顶层旧字段保持空白，将对应内容统一归入世界书对应节点单点维护。
- 启用显式 `<thinking>` 或正文 `<state>` 时，在 `regex/` 配套 `markdownOnly: true` + `promptOnly: true` 双通道剥离脚本。

### 5. 用户需求尚处于模糊探索期

- 用户希望快速获得可玩初版且无特定偏好时，默认推荐 **standard 档 + 分模块精修模式**，同时说明后续可随时按戏份升降档位。

## 资料渠道衔接

考据方法、站点列表、立绘读图与 PDB 判型执行 `cf-card-research`；检索优先调用当前环境已挂载的搜索工具，遇到站点受阻时如实记录并交接缺口。

## 分诊总纲

**先写分诊判断；少料走引导、多料走填充；档位按戏份选定；复刻角色先行多源备料；全程划清常驻泛用与下位单点归属、角色本我硬锚点与可能性空间采样。**
