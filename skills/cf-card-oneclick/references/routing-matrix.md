# 分诊与调度细则

SKILL.md 分诊拿不准、或遇到边界情况时读本文件。

> 写卡执行者只有一个：`cf-card-character`。本文件的分诊不是"选 skill"，而是选**路径**（填充/引导）和**档位**（mini/standard/full），以及决定要不要先备料。

## 分诊问题清单

用户没讲清时，在一键出卡第 0 步的那一次提问里问齐。下面是每个维度的问法和用户回答映射。

### 维度 1：资料量 → 决定路径

问法：「这个角色有原作吗？动画/小说/游戏里的现成角色，还是你自己原创的？」

| 用户信号 | 落点 |
|---|---|
| 给了作品名 + 角色名 / 贴了 wiki / 有大量设定文本 | 多料 → **填充路径**（Phase 0-5，一键流程中按直通式不停顿） |
| "我想做个……的角色" / 只有模糊想法 / 原创 OC | 少料 → **引导路径**（4 步，步步停） |
| 有一点设定但不全 | 半全 → 见下方边界情况 |

补充判定：用户给的是**作品内已存在的角色**就必须备料（哪怕他自认为很熟），凭印象写出来的卡最容易带错设定。

### 维度 2：角色戏份 → 决定档位

问法：「这角色在你的故事里戏份多重？一次性配角、主力角色，还是长线主角？」

| 用户信号 | 档位 | 体量 |
|---|---|---|
| 路人 / 群像配角 / 快速测试 / 批量生成 | **mini** | ~1000 字 |
| 主力角色 / 长期同伴 / 主要对手（**卡壳时默认**） | **standard** | ~5000 字 |
| 独占主角 / 多阶段演化 / 复杂关系网 / 高保真复刻 | **full** | 不封顶 |

→ 体量数字是参考起点，不是上下限；标准是完全符合原作性格。档位字段密度、升降档细则见 `cf-card-character/SKILL.md 里的选档表`。

### 维度 3（可选）：关口模式

一键出卡固定用直通式，不问。

| 模式 | 停顿 | 适用 |
|---|---|---|
| 交互式（默认） | 全关停 | 精修、在意细节、要中途干预 |
| 直通式 | 只停②出货、⑥定稿 | 赶时间、批量、信任 AI 内审 |

> 路径 × 档位 × 关口的完整对应表在 `cf-card-character/SKILL.md`（三个选择），本文件不复制。规律只有一句：少料走引导、多料走填充、档位只看戏份、复刻必备料。

## 边界情况处理

### 半全资料（有一点但不全）

- 先按"多料"起步，进填充路径。
- 角色技能的 Phase 0 会列出缺口；一键流程中缺口标【缺口】继续，不停下。
- 缺的是**可搜的客观设定**（生日、身高、所属组织）→ 补搜；缺的是**主观取向**（对用户的态度、边界）→ 问用户。别把这两类混着问。

### 从已有卡改 / 升降档

| 情况 | 处理 |
|---|---|
| 升档（mini→standard→full） | 展开内容 + 追加字段，**字段路径不变**（见 SKILL.md 里的选档表 升级路线） |
| 降档 / 超重卡压缩 | 走 `cf-card-character/SKILL.md 里的降档顺序`：去重→折叠→关键词化→抽样→按密度删，**不是截断** |
| 只改局部（加台词/改性格/换关系设定） | 局部修订即可，不必全流程重跑；但改完仍要跑十问终检里相关的几问 |
| 拿到的旧卡缺 relationship_frame / boundaries | 这是 v4 新增的必备结构，按 references/template.md 补齐，别当选填 |
| 旧卡里混了 `{{user}}` 动态状态、当前心情等 | 必须清掉：卡属静态区，写动态内容会污染缓存并制造矛盾（见 references/template.md） |

### 要英文输出

- **不要另起格式**。英文卡沿用同一套 schema，不另写英文专用模板。
- 做法：照常跑 cf-card-character，schema/字段路径/档位全不变，只把 value 的语言换成英文，`speech.samples` 台词按原文语言或英译按需处理。
- 提醒用户：台词英译会丢自称、口癖、句尾语气这些辨识度最高的东西，能保留原文就保留原文。

### 酒馆（SillyTavern）字段映射

字段放哪、description 怎么写，以 cf-card-format-export 第五部分的字段表为准，本文件不复制明细。这里只记最容易搞错的：

- `description` 写本卡元提示词（「你是……」），不放角色设定全文；角色设定进世界书。
- creator_notes、post_history_instructions、tags、mes_example 不写。
- `personality` 和 `scenario` **留空**。信息已在卡本体里，再填一遍就是同一信息两处维护，直接违反十问终检的「单一归属」。

默认出卡：description 放本卡元提示词，角色设定做成世界书常驻条目。

### 实在问不出需求

- 用户只想快速要个能用的、没有倾向：默认 **standard 档 + 引导路径**，门槛最低。
- 说明这是默认选择，给一句"要更轻/更重可以随时改档"的出口。

## 资料渠道

搜哪些资料、来源核实与调研方法 → `cf-card-research`。检索使用当前环境可用的工具；没有合适工具时说明缺口，不假定额外技能已经安装。本文件不复制调研规则。

## 分诊到分发的一句话总纲

**少料走引导、多料走填充；档位只看戏份（mini/standard/full）；复刻必先备料且要两源交叉验证。资料备齐就按角色技能的流程走，最后确认跑完了十问终检与五条底线。**
