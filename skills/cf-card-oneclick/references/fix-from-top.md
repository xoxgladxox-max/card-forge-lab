# 从头纠错：自上而下同步修订

适用场景：交付后作者提出修改意见，或审查发现跨层设定分歧时。

发现正文出现问题时，先写出明确诊断判断：**问题最早从哪一层产生？** 定位最高出错层后，自上而下逐层修订，最后落回正文。直接在上游源头修正规则或分界，下游节点随之一次对齐。

链路顺序（由上至下）：规划 → 节点树 → 料源索引 → 模版 → 任务书 → 验收 → 正文。

调整规范（原则改名、条目改名、字段改名或拆分扩容）时，同一轮联动完成四项检查：

1. 全工程检索旧名与新专名（`card.md`、`记录/`、任务说明、模版、各节点正文与 `keys`）；
2. 核查 `description.md` 与所有常驻蓝灯（`constant: true`）正文，将下位新增专名或绿灯触发词替换为上位泛用词，确保 `[P18f]` 与 `[P25]` 零警告；
3. 检索脚本与 `regex/` 配置中关联的字段名或标签名；
4. 运行 `check` 与 `build` 核验装配结果。

| 层级 | 对应工程位置 | 典型诊断表现 | 自该层起的联动修订顺序 |
|---|---|---|---|
| 规划 | 对话确认的体验 key、出卡单、`记录/决策记录.md` | 核心体验偏移；题材来源层级判错；多开局共享与分支边界未划清 | 规划 → 节点树 → 来源索引 → 模版 → 任务书 → 验收 → 正文 |
| 节点树 | 目录分区与 `lorebooks/` 节点划分 | 缺基底节点；单人绝活误放通用 `rule`；性质相异的概念混在同一条目 | 节点树 → 来源索引 → 模版 → 任务书 → 验收 → 正文 |
| 料源索引 | `记录/调研/00-索引.md` 与各分包 | 缺一手来源；角色口头戏称误当世界专名；主观说法当客观事实 | 来源索引 → 任务书 → 验收 → 正文 |
| 模版 | 技能模版或工程结构提案 | 选档不匹配；本我硬锚点与可能性空间采样混写 | 模版 → 任务书 → 验收 → 正文 |
| 任务书 | `记录/执行计划.md` 子项说明 | 产出范围遗漏；单次跨文体混写；把单角色局部特征扩写为全局规则 | 任务书 → 验收 → 正文 |
| 验收 | `cf-card-review`（S1～S15、C1～C28）与 `check` | 静态或语境审查漏检（如漏检思维链预填答案、漏检单向滑坡或视角越界） | 验收 → 复验全部受影响节点正文 |
| 正文 | 节点正文区 | 上游结构与边界清晰，仅局部措辞或描写需调整 | 就地修订对应节点 |

执行规范：

- 动笔前先在对话或 `记录/执行计划.md` 呈报诊断判断：哪一层产生偏差、原因是什么、波及哪些节点；涉及结构调整时经作者批准后逐层落盘。
- 需要重开已确认节点时，先请作者确认重开范围并记录原因，重开后同步复验依赖它的下游节点。
- 若问题源于技能自身的规则或模版空白，在修好当前卡工程的同时向作者报告技能改进建议。
- 维持单一事实来源：直接在原节点的源头位置修订，备份旧稿至 `backups/` 或 `候选/`，保持节点树干净无冗余补丁段。
- 区分局部内容修订与整体结构调整：针对具体描写或台词的反馈直接替换对应内容，保持已确认的节点架构稳定；涉及删除节点时先执行备份。
