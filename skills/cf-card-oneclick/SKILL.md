# 一键出卡（v2.11.0）

范围：统筹从需求分诊到成品装配的整张卡流程。各阶段正文写法执行对应领域技能，本技能负责阶段顺序、前置判断、模块边界、文体切换、标记流转、停止条件与交付报告。

总规则：

- **每阶段启动前先写出明确判断**：在 `记录/执行计划.md` 或阶段开头显式写明当前模块的边界判断（例如：哪些设定归常驻泛用统领、哪些归下位绿灯单点归属；角色哪些归本我硬锚点、哪些归可能性空间开放采样；规则与镜头怎样留出双向结果与连续梯度以消除必演剧本感），再读取对应分包动笔。
- **两种推进模式（在第 0 步出卡单确认）**：
  - **分模块精修模式（默认推荐）**：整张卡横跨客观调研报告、平实设定说明、角色本我与开放采样、角色纯口语台词、结构化总控协议、RP 小说正文等多种文本类型。每完成 1 个独立模块（如世界总纲、1 条核心规则、1 个角色、文风或第 1 条开场白），立即更新 `记录/执行计划.md` 并停下交付该模块，等作者确认或精修后再进入下一模块。
  - **全自动直通模式（作者明确选择「一口气跑完 / 中途不用停」时启用）**：在第 0 步确认出卡单后，按模块顺序逐一切换文体与只读分包连续推进至交付；中途待作者决定的事项标【提案】或【缺口】，在交付报告中统一列出。
- 单次操作聚焦同一种文本类型的一个独立模块，动笔前核准该模块的只读分包、写入路径与目标文体。
- 流程中的推断与备选方案均带标记写入，与作者明确确认的事项严格区分。
- 全程在已确认出卡单的范围内执行。

# 第 0 步：出卡单（集中提问与前置分诊）

先从用户输入提炼实际游玩时想直接体验的场景、关系、冲突、互动方式与感受方向，形成体验 key，并写出初步分诊判断。用户已说明的项直接采纳，其余未决项合并在一次提问里问齐：

| 项 | 决定什么 | 典型选项 |
|---|---|---|
| 体验 key | 整张卡围绕的核心体验；后续每个节点均服务于对应条目 | 场景、关系、冲突、互动方式、感受方向 |
| 题材来源 | 世界节点分层方式 | 原创世界 / 已知作品正传 / 衍生、IF、二创 |
| 资料渠道 | 走填充路径还是引导路径；检索范围 | 原作名与角色名、本地参考资料路径、已有卡、纯原创构思 |
| 角色戏份 | 角色起步档位 | 配角 mini / 主力 standard / 长线主角 full |
| 组成模块 | 拟建节点范围 | 世界书、多开局主角、配角、文风、五维中立思维链与状态栏、开场白数量、亲密模块、前端交互 |
| 产物形态 | 导出目标格式 | 纯文本 / 酒馆 JSON / PNG；内嵌世界书或独立世界书 |
| 工作位置 | 卡工程与成品目录 | `<卡工程根目录>/<卡名>/` 路径；改已有卡时记录原卡路径 |

- 边界情况（资料半全、改已有卡、升降档、多语种输出）按 `references/routing-matrix.md` 先行分诊，将推荐方案写入本次提问选项。
- 收到回答后，整理出卡单并附上结构提案：说明世界、角色（本我硬锚点与可能性空间划分）、文风镜头、思维链与状态栏各自采用哪些块、精简哪些块、是否启用显式 `<thinking>` 双通道剥离正则。
- 出卡单确认后，在 `<卡名>/记录/执行计划.md` 落盘执行计划（前置判断、本轮范围、阶段勾选清单、待定项），每完成一阶段或收到新指示时实时同步；完结交付后归档至 `记录/已归档计划/`，长期结论记入 `记录/决策记录.md`。
- 推进中途若需调整节点结构，在对应位置标【提案】并同步更新 `记录/执行计划.md`，于交付报告汇总。

# 六大阶段流转

| 阶段 | 调用技能 | 产物路径 | 阶段核心准则与衔接 |
|---|---|---|---|
| 1 调研 | cf-card-research | `记录/调研/{00-索引, world-*, rules-*, char-<角色>-档案与判型, char-<角色>-台词语料}.md` | 写出研究者判断（来源权重、冲突取舍、实锤与留白边界），区分口语戏称与客观专名，立绘读图记录全身客观特征与遮挡留白 |
| 2 世界书 | cf-card-worldbook | `lorebooks/world/` 下的 `world` / `location` / `rule` / `item` / `lore` 节点 | 平实说明文体；只读 `world-*` 与 `rules-*`；上位常驻纯泛用并开防递归，通用机制落实去剧本化三原则（只写动态变量与原理、守住与失守双向开放、连续梯度替代二值开关），多开局共享主角归一为开放常驻 |
| 3 角色 | cf-card-character | `lorebooks/character/` 下的 `character` / `module` / `corpus` 节点 | 每次聚焦 1 名角色；切分「本我内核硬锚点」与「可能性空间开放采样」，在 `roleplay_tips` 声明自由派生；同档位角色从各自认知功能、执念与体质差异化生长；Unit 1/2 读档案判型写设定，Unit 3 读台词语料写纯口语 |
| 4 配套 | cf-card-format-export；含前端时加读 cf-card-xiaobaix | `description.md`、`lorebooks/style/`、`output`、`message/`，以及 `regex/`、`前端源码/`、`scripts/` | Unit 1 宏观文风落盘肩扛摄像机视角边界与远中近景深梯度；Unit 2 启用显式五维中立 `<thinking>` 时同步在 `regex/` 生成 `markdownOnly` + `promptOnly` 双通道剥离脚本；Unit 3 开场白初见保持远中距视觉克制，初始 `<status>` 保持表面穿戴与暗袋泛用留白，初见陌生关系锚定 `0 ~ 15`；Unit 4 装配导出 |
| 5 审查 | cf-card-review；文体精修配合 cf-card-refine | `记录/审查报告.md` 与修订节点 | 执行 S1～S15 静态扫描与 C1～C28 语境深审（含思维链预填答案、肩扛视角越权、机制单向滑坡、可能性当打卡清单、常驻泄漏绿灯词 `[P25]`）；纯表达问题就地精修，涉及事实、归属或上游层的设计分歧标明最高出错层记入交付报告 |
| 6 装配 | cf-card-format-export 第四、五部分 | `dist/` 成品卡、备份与校验输出 | 原卡先备份至 `backups/`；运行 `check`、`build` 与双校验脚本并回读核实 |

- 各阶段基于上一阶段落盘产物推进；发现上游缺口或跨层冲突时，在源头节点标【缺口】或【提案】，保持层次清晰。

标记约定：

| 标记 | 适用情形 | 落盘位置与写法 |
|---|---|---|
| 【缺口】 | 事实缺乏可追溯来源，或多源记载相左待确认 | 节点对应位置，写明所缺信息与已查范围 |
| 【提案】 | 存在多种合理设计方案，流程先行选用其一 | 节点对应位置，写明当前选用方案与备选方案 |
| 【角色说法】 | 特定人物的主观陈述、偏见或口头戏称 | 放入该人物自身的 `character` 或 `corpus` 节点 |

每条事实保留出处与说话者归属。

遇到以下情形时立即停下并如实报告：

- 作者发出停止、先纠正或变更出卡单的指令。
- 目标路径超出出卡单约定范围，或原文件无法先行备份。
- 关键读取、写入或校验工具运行失败，影响后续真实性。
- 核心题材与人物缺乏基础材料支撑。

# 卡工程节点树

每张卡位于 `<卡工程根目录>/<卡名>/` 一级目录，`card.md` 直接置于 `<卡名>/` 根下。目录层级服务于工程归档导航，导出后各条目按自身标题、顶层包裹标签与 `order` 注入提示词。

结构示例：

```
<卡工程根目录>/<卡名>/
|-- card.md                       # 卡根：卡名、世界书名与扩展设置（YAML Frontmatter）
|-- description.md                # 顶层单槽字段：纯泛用上位总控结构（纯正文）
|-- system_prompt.md              # 顶层单槽字段（按需生成，纯正文）
|-- message/
|   |-- 0.md                      # first_mes 主开场白（纯正文）
|   `-- 1.md                      # alternate_greetings 备选开场白，按序号递增（纯正文）
|-- lorebooks/                    # 世界书目录（兼容旧名 world_book/）
|   |-- world/                    # 世界基底、分支、规则、地点、器物、历史（--- YAML --- + 正文）
|   |   |-- 01-世界总纲.md
|   |   |-- 02-核心规则.md
|   |   |-- 某地点.md
|   |   `-- 某时间线.md
|   |-- character/
|   |   |-- 主角色.md             # 本我硬锚点 + 可能性空间采样
|   |   |-- 主角色特化模块.md     # module：带 name 与 part
|   |   |-- 主角色语料.md         # corpus：纯人物口语样本
|   |   `-- 配角.md
|   `-- style/
|       |-- 01-基底文风与镜头.md
|       `-- 02-状态栏与特化文风.md
|-- regex/                        # 卡内正则（含显式 <thinking> / <state> 双通道剥离脚本）
|-- scripts/                      # 酒馆助手脚本、角色变量、小白X任务/模板/变量
|-- 记录/                         # 执行计划.md、决策记录.md、审查报告.md、调研/、已归档计划/
|-- 候选/                         # 待作者确认草稿（构建自动跳过）
|-- note/                         # 参考备注（构建自动跳过）
`-- character.png                 # 封面图
```

- `module`、`corpus` 归入 `lorebooks/character/`，在顶层标签写明 `name` 与 `part`。
- 同组条目默认按目录与文件名自动分配连续 `order`，也可在头部按组号段手写递增 `order`。
- `.md` 节点采用两类标准结构：
  - **格式 A（带 `--- ... ---` YAML 头的节点，含 `card.md` 与 `lorebooks/**/*.md`）**：第二个 `---` 下方直接写装入世界书的正文（兼容含 `<!-- body -->` 的旧文件）。`position` 取值：`before_char`、`after_char`、`"@D0"` / `"@D1"` ...
  - **格式 B（纯正文单槽文件，含 `description.md` 等顶层字段与 `message/<n>.md`）**：全文直接写纯正文。

| 类型 | 用途 | 装配去向 |
|---|---|---|
| `card` | 卡根 `card.md` | `name` 与卡级元信息 |
| `world` | 世界基底、分支总纲与泛用生态 | 常驻或触发世界书条目（1xx） |
| `location` | 地点与场域规则 | 触发条目（1xx） |
| `rule` | 机制、习俗或专项技法（写明变量维度、双向结果与梯度） | 常驻或触发条目（1xx） |
| `item` | 器物与道具（上位泛用功能先行，持有者私法归角色） | 触发条目（1xx） |
| `lore` | 历史、时间线、背景考据 | 触发条目（1xx） |
| `character` | 角色本体与多开局开放主角设定 | 世界书人物条目（2xx）；`description.md` 保留给纯泛用上位总控 |
| `module` | 角色特化子模块 | 触发条目，支持二级过滤（2xx） |
| `corpus` | 角色纯口语台词样本 | 随角色合并或独立触发条目（2xx） |
| `style` | 宏观文风、肩扛镜头与特化描写指导 | 文风条目（3xx） |
| `output` | 五维中立思维链、状态栏协议、输出契约 | `description.md` / `system_prompt.md` / 低深度条目（4xx） |
| `greeting` | 开场白，`message/0.md` 起每文件一条 | `first_mes` / `alternate_greetings` |
| `plot` | 分场次剧情底稿，`<plot name="…">` | 触发条目（5xx） |
| `event` | 局面转折、压力梯度与事件池，`<event name="…">` | 触发或概率条目（5xx） |
| `wiki` | 词条式组织、术语速查，`<lore name="…">` | 触发条目（5xx） |

- 势力组织归入 `character` 或 `wiki`，运行机制归入 `rule`，保持类型体系精简统一。
- `记录/`、`候选/`、`待归位/`、`note/`、`backups/`、`dist/`、`前端源码/` 留在工程内维护，构建器自动跳过。
- 每个节点正文保持独立完整；全卡执行「上位常驻纯泛用统领 + 下位绿灯单点归属」：常驻层（`description.md`、常驻 `world / rule / style / output`）开启防递归并使用上位泛用词统领全局，下位具体专名、物种生理、器物细则与角色个人绝活各自在对应节点单点落盘，确保 `[P18f]` 与 `[P25]` 零警告。
- 按实际体量、按需触发收益与维护清晰度决定节点拆分粒度。

# 交付报告

按以下顺序输出：

1. **出卡单与前置判断回顾**：原样列出已确认出卡单与核心架构判断。
2. **产出清单**：节点路径 / 类型 / 装配去向 / 一句话职责；成品路径；备份路径。
3. **待作者确认事项**：汇总全部【提案】与【缺口】，逐条列出所在节点、当前处理与可选方向。
4. **审查诊断结果**：列出 `cf-card-review`（S1～S15、C1～C28）发现且涉及上游决定的事项，标明最高出错层。
5. **机器校验与回读结果**：`check`、`build` 及校验脚本的实际输出与回读摘要。

以下四项状态独立表述：

- **机器校验通过**：结构、协议与打包字节核对正常。
- **已完成规定检查**：流程各单元与审查步骤已执行完毕。
- **待作者处理**：存在待拍板的【提案】或【缺口】。
- **作者确认**：作者审阅后明确拍板确认的节点状态。

# 交付后的迭代修改

- 作者提出修改意见时，切换为工程迭代模式：先在 `记录/执行计划.md` 写出诊断判断、最高出错层与分步清单，按 `references/fix-from-top.md` 自上而下同步修订（改名或扩容时同步核查常驻层与绿灯 `keys`），验证通过后归档至 `记录/已归档计划/`。
- 作者拍板采纳或移除某条【提案】时，更新对应节点与 `记录/决策记录.md`，重跑 `check` 与 `build`。
