# 一键出卡（v2.7.1）

范围：从提问到交付的整张卡流程。各阶段的写法读对应领域技能，本技能只管顺序、标记、停止条件和交付。

总规则：

- 只有一个作者确认点：第 0 步的出卡单。确认后一直跑到交付，中途不提问、不等确认。
- 领域技能里的「停下问作者」「作者确认后才继续」在本流程里改为：照常判断，把需要作者决定的内容标【提案】或【缺口】，继续做，交付时统一列出。
- 中途的推断全部带标记写入，作者交付后逐条采纳、改写或删除；没有一条写成作者确认过的内容。
- 只在出卡单范围内做，不扩大范围。

# 第 0 步：出卡单（唯一的提问）

先从用户输入里提炼玩卡时想直接体验的内容，列成体验 key。用户已说清的项不再问；其余用一次提问问齐，不逐条追问。

| 项 | 决定什么 | 典型选项 |
|---|---|---|
| 体验 key | 整张卡围绕什么写；之后每个节点都要对应到其中一条 | 场景、关系、冲突、互动方式、感受方向 |
| 题材来源 | 世界节点写几层 | 原创世界 / 已知作品正传 / 衍生、IF、二创 |
| 资料 | 走填充还是引导；去哪里查 | 原作名和角色名、本地资料文件夹、已有卡、没有资料 |
| 角色戏份 | 角色从哪一档模版起步 | 配角 mini / 主力 standard / 长线主角 full |
| 需要的部分 | 建哪些节点 | 世界书、配角、文风、回复格式与状态栏、开场白（几条）、亲密模块 |
| 产物形态 | 装配成什么 | 纯文本 / 酒馆 JSON / PNG；世界书内嵌或独立 |
| 工作位置 | 节点树和成品放哪里 | 卡工作文件夹路径；已有卡写原卡位置 |

- 边界情况（资料半全、改已有卡、升降档、要英文输出）按 `references/routing-matrix.md` 判断，判断结果写进这次提问的选项，不之后再问。
- 用户回答后，把各项整理成出卡单写在对话里，同时列结构提案：领域技能里的模板都是示例，写明世界、角色、状态栏等用哪些块、去掉哪些、新增哪些。
- 出卡单确认后，先在 `<卡名>/记录/执行计划.md` 落盘当前执行计划（本轮范围、阶段勾选清单、待定项），每跑完一阶段或收到作者新输入时实时更新；全部完成交付后归档到 `记录/已归档计划/`，`记录/决策记录.md` 只留最终结论。
- 做到一半发现结构要变：标【提案】并更新 `记录/执行计划.md` 后继续，交付时列出。

# 自动阶段

| 阶段 | 读哪个技能 | 产出 | 本流程里的处理 |
|---|---|---|---|
| 1 调研 | cf-card-research | 来源记录、事实矩阵、缺口清单 | 至少两源交叉；查不到的写进缺口，不凭印象补 |
| 2 世界书 | cf-card-worldbook | world / location / rule / item / lore 节点与触发配置 | 按题材来源定层数；先定完上位世界总纲与下位条目的拆分，确认后再进角色阶段 |
| 3 角色 | cf-card-character | character / module / corpus 节点 | 按直通式走，关口只报告不停顿，并入交付报告 |
| 4 配套 | cf-card-format-export；需要小白X前端时加读 cf-card-xiaobaix | style / output / greeting 节点，以及可选的 regex / xiaobaix-tasks.json | 只做出卡单勾选的部分；有状态栏时先定状态栏再写开场白与前端同步 |
| 5 审查 | cf-card-review；表达问题按 cf-card-refine 改 | 审查报告 | 表达问题就地修；事实、归属、上游层的问题不改，记入交付报告 |
| 6 装配 | cf-card-format-export 第四、五部分 | 卡文件、世界书、校验结果 | 原卡先备份再写；跑两个校验脚本并回读 |

- 阶段之间只看上一阶段的产出，不回头重做已完成的阶段。
- 发现上游问题：在出问题的节点里标【缺口】或【提案】继续，不在下游正文里打补丁掩盖。

标记：

| 标记 | 什么时候 | 写在哪里 |
|---|---|---|
| 【缺口】 | 事实查不到，或资料互相冲突 | 节点正文对应位置，只写缺什么，不写猜测 |
| 【提案】 | 需要作者取舍，本流程先选了一种 | 节点正文对应位置，写选了什么、另有哪些选项 |
| 【角色说法】 | 只是某个人物的说法，不是客观事实 | 只放在该人物自己的节点 |

每条事实保留来源和说话者。没有来源的不写成事实；旧稿只当线索，不当证据。

仍会立即停下并报告，不用看似完整的产出掩盖：

- 用户说停止、先纠正，或改了出卡单。
- 写入位置超出出卡单的工作位置，或要覆盖无法备份的文件。
- 工具失败导致后续无法真实执行（读不到资料、校验脚本跑不了、写入失败）。
- 关键资料一条都没有，整张卡只能靠编造。

# 卡的节点树

一张卡是 `<卡工程根目录>/<卡名>/` 下的一个一级文件夹，每个设定是一个带类型的 `.md` 节点。**不在 `<卡名>` 外再套一层作品目录，也不在 `<卡名>` 内再套一层子目录放 `card.md`**；`card.md` 必须直接位于 `<卡名>/` 一级根部。树只负责组织和导航；层级关系不进提示词，导出后每条各自注入，所以层级写在标题和正文里。

结构示例（文件名换成当前卡的实际内容）：

```
<卡工程根目录>/<卡名>/
|-- card.md                       # card：卡名、世界书名、留在卡里的扩展设置（带 --- 头时末尾必有 <!-- body -->）
|-- description.md                # 单槽字段（空字段不生成；纯正文不写 <!-- body -->）
|-- system_prompt.md              # 单槽字段（按需）
|-- message/
|   |-- 0.md                      # first_mes（纯正文不写 <!-- body -->）
|   `-- 1.md                      # alternate_greetings，从 1 起
|-- world_book/
|   |-- world/                    # 世界、地点、规则、道具、历史（每条带 --- 头 + <!-- body -->）
|   |   |-- 基底世界.md
|   |   |-- 分支世界.md
|   |   |-- 某地点.md
|   |   `-- 某时间线.md
|   |-- character/
|   |   |-- 主角色.md             # 人格、外貌、言语、行为逻辑
|   |   |-- 主角色特化模块.md     # module：名字带所属
|   |   |-- 主角色语料.md         # corpus
|   |   `-- 配角.md
|   `-- style/
|       |-- 基底文风.md
|       `-- 特化文风.md
|-- regex/                        # 拆出的正则（<序号>-<名>.json + .html）
|-- scripts/                      # 拆出的脚本（<序号>-<名>.json + .js、variables.json、xiaobaix-tasks.json）
|-- 记录/                         # 执行计划.md（动态进度，完结归档）、决策记录.md（只留最终结论）、旧原稿（SKIP_DIRS 自动跳过）
|-- 候选/                         # 待确认草稿（SKIP_DIRS 自动跳过）
|-- note/                         # 备注资料（SKIP_DIRS 自动跳过）
`-- character.png                 # 封面图
```

- module、corpus 放 `world_book/character/`（或平铺在 `world_book/`），所属写进名字和 part。
- 同组顺序默认按文件名；要调整在节点头写 order，不改名。
- `.md` 节点文件严格遵守两种格式（与 `cf-card-project`、`cf-card-format-export` 的写法一致）：
  - **格式 A（带 `--- ... ---` YAML 头的节点，含 `card.md` 与 `world_book/**/*.md`）**：第二个 `---` 下方**必须有且仅有一行 `<!-- body -->`**（否则报 `[P1]` 阻断构建）；`---` 与 `<!-- body -->` 之间放可选 `## 工序` 段，`<!-- body -->` 之后才是装入卡的正文（`card.md` 无正文也必须在末尾保留 `<!-- body -->`）。`position` 仅限 `before_char`、`after_char`、`"@D0"` / `"@D1"` ...
  - **格式 B（不带 `---` 头的纯正文文件，仅限 `description.md` 等顶层单槽字段与 `message/<n>.md`）**：不写 `---` 头时**禁止写 `<!-- body -->`**；一旦加了 `---` 头就必须按格式 A 加 `<!-- body -->`。

| 类型 | 是什么 | 导出去处 |
|---|---|---|
| `card` | 卡根 `card.md` | name 和卡元信息 |
| `world` | 世界观；基底和分支各一个节点 | 常驻条目 |
| `location` | 地点，所属写进正文 | 触发条目 |
| `rule` | 机制或规则，正文写明在哪一层生效 | 触发条目 |
| `item` | 关键物 | 触发条目 |
| `lore` | 历史、时间线、背景设定 | 触发条目 |
| `character` | 角色；主角配角同型，配角只有一个文件 | 主角常驻条目，配角触发条目；`description.md` 留给本卡元提示词 |
| `module` | 角色子模块（特化玩法、专属机制） | 触发条目，可配二级过滤 |
| `corpus` | 台词锚点、对话示例 | 随角色进同一条目，或单独成触发条目（不用 mes_example） |
| `style` | 文风；基底常驻，特化带使用条件 | 文风层条目 |
| `output` | 思维链、状态栏、语言原则 | `description.md` / `system_prompt.md` / 低深度条目 |
| `greeting` | 开场白，`message/0.md` 起每文件一条 | first_mes / alternate_greetings |
| `plot` | 按场次推进的剧情底稿，`<plot name="…">` | 触发条目，5xx |
| `event` | 改变当前局面的事件、压力档位、随机事件池，`<event name="…">` | 触发或概率条目，5xx |
| `wiki` | 词条式术语、组织、地名速查，沿用 `<lore name="…">` | 触发条目，5xx |

- 类型存在的依据是酒馆卡有对应槽位，或本工作流约定的世界书分组。势力组织用 `character`；机制本身（如压力档位怎么推进）用 `rule`。不另造类型。
- `调研.md`、`记录/`、`候选/`、`待归位/`、`note/`、`backups/`、`dist/` 不进卡。
- 每个节点正文自包含，不写「如前所述」，也不写指向其他节点的引用说明。重要内容（核心体验、硬规则、模型容易忽略的限制）在不同位置重复三次左右，每处承担不同功能；一般设定只在主归属节点写一次。
- 树是形状上限，不是必填清单。拆不拆看三点：体量大不大、有没有按需加载的场景、拆开能不能真正省篇幅。

# 交付报告

按顺序：

1. 出卡单：原样复述。
2. 产出清单：节点 / 类型 / 导出去处 / 一句话；成品路径；原卡备份路径。
3. 待作者处理：全部【提案】和【缺口】，逐条写节点、内容、选项或缺什么。
4. 审查结果：发现但没改的问题，写明最早出错在哪一层。
5. 机器结果：两个校验脚本的结果和回读结果。

以下状态分开写，不互相替代：

- 机器校验通过：只说明格式和装配没问题。
- 已完成规定检查：只说明流程跑完。
- 待作者处理：仍有提案或缺口。
- 作者确认：只有作者看过并明确确认后才这样写；流程跑完时，除出卡单外都不是这个状态。

# 交付后的修改

- 作者提出修改：不再按一键模式自动跑，先在 `记录/执行计划.md` 写明本轮修改范围与分步清单，按 `references/fix-from-top.md` 从最早出错的层往下改；执行期间随作者输入实时更新计划，改完并核对通过后归档到 `记录/已归档计划/`。
- 作者只采纳或删除某条【提案】：直接改对应节点，更新计划勾选并重新装配一次。
