# 配套（v3.17.0）

范围：世界和角色以外一张卡还需要的部分：文风、回复格式、开场白、装配导出。各部分独立，按需查阅对应章节。

## 总规则

- **每步动笔前先写出明确判断**：在编写文风、总控协议、状态栏或开场白前，先用两三句话写出明确判断，说明该模块如何引导扮演模型的叙事节奏与视角焦点、哪些属于固定格式锚点、哪些留给现场气氛发挥。
- **结构提案先行**：文风块骨架、状态栏字段与篇章生成器均提供起点参考；动笔前先结合当前卡提出结构提案（启用哪些块、记录哪些跨回合变量、开几条开局），作者确认后再写。第五部分的卡文件格式直接遵循酒馆导入规范。
- **单一归属与精炼有效**：每条规则只放在最合适的一处，专注写当前卡特有的叙事坐标、视角边界与输出结构，省去空泛常识与虚空防御句。
- **守住玩家主体权**：叙事停在等待 `{{user}}` 回应的节点，把 `{{user}}` 的台词、动作、心理与决定完整留给玩家输入。
- **区分固定格式锚点与开放空间**：
  - **固定锚点与格式协议（写准）**：流派坐标、叙述人称与受限视角、对白标点格式、开场白有据可查的事实前提、回复各块的标签包裹、状态栏与世界书联动的阶段锚点格式、JSON / PNG 导入结构。
  - **随境变化的描写与状态（给开放方向）**：文风中的具体镜头落点、动作与身体反应、感官参考词例、开场白中未定死的背景成因、状态栏里随剧情演化的描述项，先写一句上位原则，再用 **「平时/通常……」「有时……」「一些情况下……还有一些情况下……例如……」「在特殊情况下……」** 给出启发方向与例子，让模型顺着现场情境自然延展。
- **按文本类型划分工程区域与四步独立交付方案**：

| 单元 | 前置判断与模块 | 只读范围 | 只写范围 | 文体与交付节点 |
|---|---|---|---|---|
| **Unit 1 文风模块** | 先写出流派坐标与远近镜头颗粒度判断；编写宏观基底文风（蓝灯）+ 特化感官文风（绿灯） | 世界总纲 + 主角色核心设定 | `lorebooks/style/*.md` | **指导说明文体**（附 200～500 字基准样例段） → **写完停下确认语感** |
| **Unit 2 状态栏与回复格式** | 先写出常驻泛用边界与跨回合追踪需求判断；编写总控协议、思维链与状态栏 | 世界规则（数值/阶段门槛）+ 角色阶段条目头 | `description.md` / `system_prompt.md` 或 `lorebooks/output/*.md` | **结构化协议文体**（固定协议写准，动态项留出弹性） → **写完停下确认协议** |
| **Unit 3 开场白** | 先写出开局站位、视角焦点与留扣位置判断；编写主开场白与备选开场白 | `lorebooks/style/` + 状态栏协议 + 本场登场角色与地点节点 | `message/0.md`、`message/1.md`... | **纯 RP 小说正文文体**（先交付 `message/0.md` 核对语感与状态栏，通过后再写其余开局） |
| **Unit 4 装配导出** | 核对节点头、分组编号与防递归配置；构建 JSON / PNG 并跑校验脚本 | 全部进卡源区文件 | `dist/` 与 `backups/` | **工程校验报告**（运行 `validate-worldbook.ps1` 与 `validate-card.ps1` 并回读核实） |

# 一、文风

文风块负责四件事：立住可信的日常基底、用成熟流派与作品锚定语感坐标、按空间距离调节描写颗粒度、在块末用基准样例段带出正文语态。

## 宏观与微观分层

| 层级 | 定位 | 承载内容 | 触发方式 |
|---|---|---|---|
| 宏观（基底文风） | 全卡共用的上位叙事方向 | 流派与作家参照、语体温度、受限视角、四级镜头规律、对白与潜台词原则、基准样例段 | 常驻蓝灯 |
| 微观（特化文风 / 场景文风） | 特定区域、氛围或专项互动的下位质感 | 明确的启用与退出场景条件、该场景独有的感官切面、具象参考词例与分档示例 | 条件绿灯 |

- 微观模块写明可判断的客观启停条件（具体地点、独处氛围或特定互动开启与结束），进入时补充该场景特有的感官肌理，退出后自然回归宏观基底。
- 作者为单卡专门指定的风格偏好或服饰、视角要求，按适用范围放入宏观或对应微观模块并妥善保留。

## 基准样例段与末尾正文语态

模型续写时受最贴近对话末尾的语态影响最深。把基准样例段放在宏观文风块最末尾，能直接把模型带入饱满的小说叙事语态：

- 篇幅一至两段（约 200～500 字），标明「例」，完整示范本卡的语体、受限视角、动作质感与对白节奏；作者有钟爱的参考片段时可直接选用。
- 样例段专注描写在场角色与环境氛围，作为语感示范，正文中按当下新场景重新创作意象与动作。
- 贴近对话末尾的 `@D0` / `@D1` 状态信息保持简短精炼，把完整长规则放在 `before_char` 或 `after_char`。

## 镜头：肩扛跟拍视角、四级双轴聚焦与颗粒度缩放

动笔前根据本卡核心体验确定镜头停留重心，按「当处于 X 情境时 → 聚焦 Y（把握分寸 Z）」正面陈述：

- **肩扛跟拍视角与取景框边界**：
  - **取景框与遮挡盲区**：默认采用贴在 `{{user}}` 肩侧的动态跟拍镜头，呈现取景框内当场可感知的光影轮廓、声响、温差、气味与触感，保留门后、箱底、袖中暗袋等真实的视线遮挡盲区；只写逼向 `{{user}}` 的外部感官信号，把紧张、畏惧或兴奋等情绪定义权完整留给玩家。
  - **初见与远中距景深节制**：角色初登场或处于全景、中距时，先抓整体身形剪影、步态气场与两三处最醒目的穿戴视觉锚点，待视线停留端详或距离拉近时再渐次浮现内衬叠穿、花纹与贴身细节。
  - **视角切换闸门**：当 `{{user}}` 明确指定切换视角，或推入贴身微观交锋需要呈现对手内部体感与心防松动时，可短暂切入该在场角色的感知与『』心声，呈现完毕后自然收回跟拍主视角。
- **四级双向推拉与起点承接**：叙事焦距在「全景 ↔ 中距 ↔ 近距 ↔ 微观」四级之间平滑缩放，由「感官聚焦（物理与动作维度）」与「情感聚焦（话语与心绪维度）」两条独立轴协同推进。每轮直接承接上一轮结束时的距离深挖或向相邻层级平滑过渡，接触撤开或拉开距离时自然拉回中距或全景。
- **远宽近细的四档独立颗粒度**：
  - **全景**：聚焦空间格局、身形剪影、主色调轮廓、站位、步态与远距声响，点染留白勾起画面感；
  - **中距**：聚焦两三处醒目穿戴锚点、局部动作张力、衣料随动作牵动的轮廓与视线交汇；
  - **近距**：展开贴身可感的体温、呼吸、气味、材质触感与细微摩擦；
  - **微观**：深入刻画局部肌理、受力形变、温湿度交融与深层感官联动。
- **对白潜台词与性格区分**：角色说出口的话服从其自身性格与当下意图。城府深或设局试探者在全景与中距多用日常场面话留白，靠停顿和动作细节传递潜台词；坦率守规者在需要表明态度或提醒规矩时直接把话说清；害羞、嘴硬或试图遮掩异样者则会说出贴合处境的借口与粉饰之词，避免一刀切封杀解释性台词把鲜活角色变成哑巴。
- **特化感官文风的四层拆分**：
  1. **第一、二层（常驻蓝灯共用）**：放顶层 `镜头聚焦` 总则及 `感官聚焦`、`情感聚焦` 在四级下的泛用规律，保持零具体部位与零特化词例，让日常剧情视野开阔。
  2. **第三、四层（按专项拆为独立条件绿灯）**：每个独立主题单独成条，第三层按「1. 全景 / 2. 中距 / 3. 近距 / 4. 微观」四档写出该主题的观察重点，具体部位与动作放入 `(e.g., ...)` 并注明随角色性格与现场情况自然推进；第四层用 `维度轴: e.g., 词例1, 词例2, ... etc.` 提供开放的具象质感参考词例，引导模型结合现场材质与受力延展鲜活词汇。

四级双轴聚焦上位模板（示例，按当前卡改写）：

```yaml
镜头聚焦:
  性质: 叙事焦距随互动在「全景 ↔ 中距 ↔ 近距 ↔ 微观」四级之间平滑推拉，重在铺垫与演进过程；每轮直接承接上一轮结束时的镜头距离，在当前级深挖或向相邻层级自然过渡。
  颗粒度: 四级对应远宽近细四档颗粒度，远景简练勾勒空间剪影与动静留白，近景细腻展开局部肌理、体温气味与受力变化。
  双轴协同: 由「感官聚焦」与「情感聚焦」两条独立轴组成，各自随空间距离与心理防线推进或收束，既可同频升温，也可形成外冷内热或嘴硬身软的错位层次。
  节奏把握: 气氛与铺垫尚在累积时稳住当前层级细腻展开，随角色意图、双方互动反馈逐步推进或拉远留白。

感官聚焦:
  性质: 物理描写随空间距离与接触深度在四级颗粒度间自然缩放。
  分级:
    - 全景（远距或日常过场） → 勾勒身形剪影、衣着轮廓、站位距离、步态与环境声响
    - 中距（视线停留或动作起势） → 捕捉衣料牵动、肢体蓄力轮廓与视线交错
    - 近距（贴近独处或初步触碰） → 呈现近处可感的重量、体温、气息、衣料摩擦与撤手后的余温
    - 微观（深度接触或情绪浓烈处） → 交织刻画局部肌理、力道传导、细微战栗、湿润度与呼吸声响

情感聚焦:
  性质: 台词与心绪延续角色日常性格基底，随信任与防线变化在表层话语与深层心意之间自然流转。
  分级:
    - 全景（公开场合或保持社交距离） → 呈现符合身份的日常交谈与举止；坦率者直言其事，含蓄或设局者通过停顿与视线落点留白
    - 中距（试探周旋或借故掩饰） → 台词贴合性格展现层次：或借日常由头半真半假试探，或为掩饰异样找借口粉饰，配合细微神态展现言行张力
    - 近距（距离拉近或防线松动） → 场面话逐渐松口，浮现引导、追问、嘴硬退让及简短贴身思绪
    - 微观（卸下防备或情动深处） → 直白流露真实心意、本能反应与当下冲动；平复拉开距离后自然回落至角色惯常口吻
```

## 文风坐标与外语语感转化

- **具象流派锚定**：用具体作家、作品或成熟流派定调（如武田绫乃的青春群像微动作、张爱玲的古典白话世情肌理、钱德勒的冷硬派快节奏交锋），并提炼出两三条可落地的句式与镜头习惯，把零散短句融进连贯的环境光影与人物动作中：
  - 连贯白描示例：换气扇规律的嗡鸣拉长了室内的安静。她指尖在亮起的屏幕上轻轻一划，视线越过谱架边缘扫过来，右嘴角那颗细小的痣随着浅淡笑意微微上提。
- **外语素材重造**：遇到日文或英文原句口癖时，识别其在场面上承担的拉近、施压或撒娇作用，用自然地道的简体中文句式、停顿和喉音呼吸白描重现同等味道。

# 二、回复格式、`description.md` 与状态栏

动笔前与作者确认五项基础约定：每轮回复组成部分与顺序、状态栏追踪字段、思维链采取隐式还是显式、叙述人称与受限视角、对白与独白标点格式。

## 放置位置分工

| 位置 | 特性 | 承载内容 |
|---|---|---|
| `description.md` | 每轮常驻且参与世界书扫描 | 纯泛用的 GM 主持定位、世界基调上位概括、叙事推进与玩家输入处理规则、视角边界与输出结构（全程使用上位泛用词，保持对具体角色名、地名、器物名等绿灯触发词的零引用） |
| `system_prompt.md` | 角色专属系统提示位 | 按需放置输出规范补充 |
| 低深度世界书条目 / `depth_prompt` | 贴近最新对话轮次注入 | 换预设也需稳定生效的状态栏格式模板（同样使用泛用说明） |

## `description.md` 标准结构（官方五段标签 · 纯泛用上位总控）

从草稿整理常驻总控时，先将具体专名与支线细则提炼为通顺的上位泛用词（例如用「各方阵营人物与异类族群，具体设定由当前激活的世界书条目动态提供」统领登场对象，用「遵循当前激活条目的专属法则、成立条件与阶段尺度」统领交互规则），确保逻辑饱满且 `[P25]` 零绿灯泄漏。

在 `<instructions>` 中赋予在场角色主动的生命力：除了响应 `{{user}}` 的行动外，在场角色也会依照自身性格动机、手头事务或暗中盘算主动发起日常搭话、试探或制造契机，让世界在日常闲暇与冲突交锋时均保持鲜活运转。

```xml
<role>
你是《[卡名]》的叙事者与游戏主持人（{{char}}），负责演绎除 {{user}} 以外的登场人物与世间百态，推动故事自然运转。
默认采用紧跟 {{user}} 的第三人称受限跟拍视角：镜头如贴在 {{user}} 肩侧的摄像机，捕捉取景框内当场可感知的光影轮廓、声响、温湿度、气味与肢体触碰，保留真实的视线遮挡盲区；当 {{user}} 明确指定切换视角，或进入贴身微观交锋需呈现对手内部体感与心防变化时，可短暂切入该在场角色的体感视角与『』心声，随后收回主视角。
</role>

<context>
- [1～2 句用上位泛用词概括世界时代基调、日常秩序与核心生态]
- 具体地域风物、阵营法则、器物机制与登场人物档案均由当前激活的世界书条目动态提供；各条目中的具体台词与动作示例均为标定气韵的可能性采样，优先顺着角色本我内核与现场态势自由推演。
</context>

<instructions>
- 导演控场与人物能动性：
  - 结合当前时空场景、前文脉络、在场人物底层人格（personality）与状态变化，给出贴合人物本我的自然回应；在场人物拥有各自的生活节奏与盘算，会顺着自身性格与处境主动交谈、行事、试探或设局。
  - 把握远近景深与渐进梯度：初见或远中距时先抓整体剪影、步态气场与两三处核心视觉锚点，随视线停留或距离拉近再渐次展开服饰细节与贴身感官；遇到试探或冲突时按渐进梯度呈现环境前兆、言语周旋与实质交锋，并在交还 {{user}} 回应的自然节点干净停笔。
- 玩家输入衔接：
  - 简略意图补全：当 {{user}} 给出简短行动方向时，结合其当前身份能力与随身器物，顺畅补全合理的动作细节并呈现周围反馈。
  - 规则与尺度呼应：当 {{user}} 的举动触及世界客观规律、能力上限或人物当前阶段边界时，通过场内人物的真实应对与渐进规则反馈自然呈现结果；客观呈现逼向 {{user}} 的外部感官信号，将 {{user}} 自身的情绪定义权完整留给玩家。
- [用上位泛用词写明本卡重点场面的感官与互动质感要求，如：遵循当前激活条目的专属规则、连续梯度与成立条件，细腻呈现衣饰动静、肢体距离、体温气息与双向开放的攻守演化]
</instructions>

<constraints>
- 完整保留 {{user}} 的主体权，将 {{user}} 的台词、后续动作、内心想法、临场决定与主观情绪定义全部留给玩家。
- 守住取景框盲区与景深颗粒度：正文聚焦当前跟拍镜头取景框内可感知的言行与物象，遮挡物内部、未知前史与未揭晓底牌保持留白；远中景通过神态、停顿与场面话传递潜台词，贴身『』独白随近距或微观自然浮现。
- 所有登场人物与 {{user}} 共同遵循本世界的客观法则、状态门槛与生理逻辑。
</constraints>

<output_format>
- 人物说出口的对白使用「」，贴身流露或独处时的内心独白使用『』。
- 每轮回复按既定顺序输出：[`<thinking>` 极简五维推演（启用显式思维链时）→ ]叙事正文 → `<status>` 状态栏（状态栏客观更新当前已生效状态；尚未在剧情中揭晓的暗袋底牌用泛用词留白）。
</output_format>
```

## 思维链（输出前预处理与双通道剥离正则）

- **隐式预处理（默认推荐）**：规则清晰或使用带原生推理能力的模型时，直接由 `description.md` 的 `<instructions>` 引导模型在内部完成意图衔接与视角核对，保持输出干净。
- **极简五维中立 `<thinking>` 协议（按需启用，零预填战术答案）**：当卡内包含跨回合多轨数值、信息差博弈或复杂阶段切换时可启用。只给 5 个中立思考维度，保持零预设固定战术、零摘抄上文旧句，并通过第 4 步「平庸反应 vs 人物独有反应」对比激发模型的现场创造力：

```xml
<thinking>
1. 意图与前文校准：[{{user}} 本轮行动的实际意图与潜台词；若有简略或越界输入如何自然衔接，本轮需规避何种重复惯性]
2. 物理坐标与景深：[当前跟拍镜头主角与视线遮挡盲区｜承接四级焦距的哪一级（远宽近细）]
3. 本我驱动与主观猜测：[在场角色基于底层 personality、核心执念与当前状态，对 {{user}} 行动的主观猜测（保留因认知局限猜错的可能）与真实诉求]
4. 反套路推演：[顺手最平庸俗套的反应是什么 → 结合该角色独有性格、随身器物与现场环境，更鲜活且具辨识度的具体言行是什么]
5. 结算与留白停点：[核对连续梯度或阶段门槛，本轮哪些状态发生实质变化 → 推进到哪个交还 {{user}} 抉择的瞬间干脆停笔]
</thinking>
```

- **显式思维链必配 `regex/` 双通道剥离脚本**：凡启用显式 `<thinking>`，在 `regex/` 下同步配置一条同时开启 `markdownOnly: true`（前端显示隐藏）与 `promptOnly: true`（发送历史上下文前剥离 `<thinking>[\s\S]*?</thinking>\s*`）的 `regex_scripts`，保持界面整洁并防止历史楼层思考文本堆积污染后续语态。

## 状态栏（防暗牌剧透与初见关系锚定）

- **聚焦已生效状态与未揭晓暗牌留白**：记录跨回合持续生效或本轮发生实质变化的客观项（日期时辰、所处地点、表面可见穿戴与随身物变化、身体状态、关系进展）。对于尚未在剧情中显露的暗袋底牌或隐藏真相，在状态栏（尤其开场第 0 轮初始 `<status>`）中以泛用词（如「袖中防身器物」「随身旧物」）留白，保护探索悬念。
- **初见陌生关系锚定**：初见无交集的陌生人物，初始关系分值锚定在 `0 ~ 15`（无感情试探或礼貌善意）区间；仅对受特定执念或身份规则将 `{{user}}` 认作特定对象的人物按其专属机制设定，并在状态描述中注明属于单向执念投射。
- **阶段与事件联动锚点**：卡内设有角色阶段 `module` 或单次 `event` 条目时，在状态栏指定栏位或尾部隐藏注释（如 `<!-- 角色_关系:<X/100 阶段一> -->`）输出清晰的阶段名（多轨并存时错开命名如 `阶段1` 与 `第一阶段`），配合世界书 `scan_depth: 1` 精准切换。
- 各条开场白末尾附带格式完全一致的初始状态栏，每次数值波动均与当轮正文事件自然呼应。

# 三、开场白

- **`first_mes` 与 `alternate_greetings`**：`message/0.md` 对应首条开场白，`message/1.md` 起对应左右滑动切换的备选开局；存在多开局或可选扮演视角时，可将其中一条设为篇章生成器（见 `references/generator-template.md`），其余条目承载各条具体开局正文。
- **初见景深对齐与纯正小说开场质感**：直接用环境光影、器物声响与角色的动作台词演活当下这一幕。初见人物处于全景或中距时，先捕捉光影轮廓、步态声响与 2～3 处最具视觉冲击力的核心穿戴特征，把内衬细节留待后续拉近距离时渐次展开；在角色抛出一句问话、递来一件器物或突发一桩待决之事的瞬间干净停笔，把回应权交给 `{{user}}`。
- **前提有据或留白开放**：开场交代的处境与异常若有原作或确认设定支撑则准确写出；原因尚未锁定时只客观描写眼前现象（例如写「信使比平日晚到了半个时辰」），把成因留给后续探索。
- **多开局各自独立鲜明**：每条备选开局切入不同的时间节点、初始地点、身份起点或事件局面，人称、标点与末尾初始状态栏格式保持全卡统一。

# 四、装配：内容放进卡的哪里

1. **节点文件与目录协议**：
   - **格式 A（带 YAML Frontmatter 的节点文件：`card.md`、`lorebooks/**/*.md`）**：头部 `--- ... ---` 填写触发配置，下方直接写带顶层 XML 标签的正文（`card.md` 只需写 YAML 块；兼容含 `<!-- body -->` 的旧节点文件）。
     - `position` 取值：`before_char`、`after_char`、`"@D0"` / `"@D1"` / `"@D2"` ...（带 `@` 加双引号）。
     - `type` 取值：`card`、`world`、`location`、`rule`、`item`、`lore`、`character`、`module`、`corpus`、`style`、`output`、`greeting`、`note`、`plot`、`wiki`、`event`。
     - 常用触发字段：`constant`、`enabled`、`keys`、`secondary`、`selectiveLogic`、`scan_depth`、`recursion`（或 `exclude_recursion`、`prevent_recursion`）、`probability`、`ignore_budget`。
     - **`title` 与文件名同步**：非角色条目 `title` 直接写最短自然名称（与去掉数字前缀后的文件名及 `<标签 name="...">` 保持一致）；多角色卡的 `character` 条目可采用「阵营 · 角色名」，`<character name="角色名">` 保持角色本名。重命名条目文件时同步更新 `title`、顶层标签属性与关联引用。
   - **格式 B（纯正文单槽文件：顶层 `<字段>.md` 与 `message/<n>.md`）**：全文直接作为对应字段（`description.md`、`scenario.md`、`system_prompt.md` 等）或开场白的正文装入。
2. **层级深度参考**：世界观与社会底子 `@D4` → 法则与专项机制 `@D3` → 角色与阶段模块 `@D2` → 文风 `@D1` → 输出与状态校准 `@D0`。
3. **三明治包裹（按需选用）**：多条同组模块确需共用首尾外框时，同目录建立 `wrap: head` 与 `wrap: tail` 节点，保持常驻、`ignore_budget: true`、同 `position` 与深度，并分别置于组内最小与最大 `order`。
4. **节点顶层包裹对照表**：

| 节点类型 | 顶层包裹标签 | `title` 示例 |
|---|---|---|
| `world / location / lore / rule / item` | `<world name="…">`、`<location name="…">`、`<lore name="…">`、`<rule name="…">`、`<item name="…">` | 区域世界观、宵禁通行规则 |
| `character` | `<character name="角色名">` | 角色名（多阵营卡可写 `阵营 · 角色名`） |
| `module / corpus` | `<character name="角色名" part="模块名">` | 角色阶段二、角色日常语料 |
| `style` | `<style name="文风名">` | 基底文风、雨夜港口文风 |
| `plot / wiki / event` | `<plot name="…">`、`<lore name="…">`、`<event name="…">` | 剧情名、机构志、事件名 |
| `output` | 进 `description.md` 免外层包裹；进世界书用 `<output>` | 输出与状态栏规范 |
| `greeting` | 纯正文免包裹 | — |

5. **分组编号与校验**：新建卡按组连续编排 `order`（世界 `1xx` → 人物 `2xx` → 文风 `3xx` → 输出 `4xx` → 开场白及其他 `5xx`）；导出后依次运行 `scripts/validate-worldbook.ps1` 与 `scripts/validate-card.ps1`。

# 五、装配：卡文件格式

范围：SillyTavern 角色卡 JSON / PNG 外层结构与导入校验（源码依据见 `references/card-format-sources.md`）。

## 载体与版本

| 载体 | 存储结构 | 酒馆读取逻辑 |
|---|---|---|
| `.json` | UTF-8 无 BOM 的卡 JSON 对象 | 按 `spec` 识别 V2 / V3 并读取 `data` |
| `.png` | PNG `tEXt` 数据块（`chara` 存 V2，`ccv3` 存 V3，值为 JSON 的 UTF-8 Base64） | 优先读取 `ccv3`，无则读取 `chara` |
| `.charx` | V3 ZIP 包（根目录 `card.json` + `assets/`） | 酒馆支持导入 |

默认输出兼容性最广的 **V2 格式**（`chara_card_v2` / `2.0`）：

```json
{
  "spec": "chara_card_v2",
  "spec_version": "2.0",
  "data": {
    "name": "", "description": "", "personality": "", "scenario": "",
    "first_mes": "", "mes_example": "",
    "creator_notes": "", "system_prompt": "", "post_history_instructions": "",
    "alternate_greetings": [],
    "character_book": { "entries": [], "extensions": {} },
    "tags": [], "creator": "", "character_version": "",
    "extensions": {}
  }
}
```

## 核心外层字段说明

| 字段 | 职责与使用约定 |
|---|---|
| `name` | 卡名（即 `{{char}}`），顶层可同步保留同名 `name` 兼容旧工具 |
| `description` | 本卡常驻总控元提示词 |
| `personality` / `scenario` | 简短摘要或场景说明，常规大卡可留空串 `""` 交由 `description` 与世界书承载 |
| `first_mes` / `alternate_greetings` | 首条开场白与备选开场白数组 |
| `mes_example` / `post_history_instructions` | 常规工作流保持空串 `""`，台词语料放入世界书角色或语料条目 |
| `creator_notes` / `tags` | 给玩家阅读的启用说明（如前端扩展开关提示）与分类标签，不注入模型提示词；无需要时保持空串 `""` 与 `[]` |
| `system_prompt` | 角色专属系统提示，空串时沿用用户当前预设主提示词 |
| `character_book` | 内嵌世界书对象（含 `entries` 数组与 `extensions` 对象） |
| `extensions` | 扩展数据对象（如 `depth_prompt`、`talkativeness`、`regex_scripts`），原样保留未知扩展键 |

## 文档转卡流程

将散装设定草稿整理为可导入卡文件时：

1. **通读归类**：按总控说明（进 `description`）、世界与地点规则（进 `character_book` 世界组）、角色档案与台词（进 `character_book` 人物组）、文风与状态栏（进 `style / output` 或 `depth_prompt`）、开场白（进 `first_mes` 与 `alternate_greetings`）、场外附言（单列交还或按作者意愿放 `creator_notes`）理清去向。
2. **保真搬运**：整理归位阶段忠实保留原稿文字，归属待定的段落与称呼宏替换（是否转为 `{{user}}` / `{{char}}`）先请作者确认。
3. **序列化生成与双脚本校验**：使用程序序列化写出 UTF-8 无 BOM 的 JSON，按需用 `scripts/embed-png.ps1` 嵌入封面 PNG，并运行校验脚本回读确认。

```powershell
# 嵌入 PNG 封面
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/embed-png.ps1 -Card .\某角色.json -Image .\封面.png -Out .\某角色.png

# 校验卡外层结构与世界书条目
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/validate-card.ps1 -Path .\某角色.png
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/validate-worldbook.ps1 -Path .\某角色.json
```
