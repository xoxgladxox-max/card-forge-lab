# 世界书设计指南（进阶）

条目粒度切分、关键词设置、递归控制、互斥组与角色阶段条目的设计方法。底层 JSON 字段规范见 `entry-spec.md`。

## 一、条目粒度

一个条目对应一个性质独立、可单独唤起的实体或主题：

| 类型 | 粒度 | 位置建议 |
|---|---|---|
| 世界基底 | 1 条常驻总纲（上位世界观、时代与基本秩序，精炼统领） | `before_char` |
| 地点 | 一地一条（建筑、街区、据点） | `before_char` |
| 角色 | 一人一条（篇幅随戏份展开） | `before_char` |
| 组织 / 物种 | 一组织或一类物种一条 | `before_char` |
| 法则 / 专项机制 | 按性质拆条，保持单条概念纯粹 | `after_char` |
| 状态 / 阶段模块 | `@D2` ～ `@D0`，贴近最新对话轮次 | `position: 4` |

切分判据：

1. **常驻与按需分层**：全线每轮都要用的泛用底子留常驻总纲；特定对象、地点、器物与支线拆成下位绿灯。
2. **性质相异则物理独立**：成因、运作逻辑或触发语境不同的两个概念各自独立成条，避免混装在同一条里互相牵连。
3. **同类短项合集归档**：同一模块下并列小设定较多时，上位总纲保留一句泛用总括，具体短项合为 1 条下位「同类合集条目」（绿灯，`keys` 填各项名称）；某项需要深度展开时再单独成条。
4. **同类紧邻编排**：同一大类内按「上位总纲 → 同类下位专项」紧邻排列并连续编号。

## 二、关键词设计

1. **覆盖实际叫法与通俗词**：包含本名、外文或译名、简称、绰号；若正文将现代概念转化为世界观本土术语，把玩家常用的通俗叫法一并保留在 `keys` 中。
2. **地点联动驻地人物**：长期驻守某地的角色，可在该地点条目开启单向递归，或在角色 `keys` 中视情况加入核心专属驻地名。
3. **选用高辨识度专名**：关键词使用指向明确的专名或双字以上特征词，确保精准命中目标场景。
4. **正则合并同源变体**：把单个 key 写成 `/角色本名|外文名/i` 即可一条覆盖多变体（源码 `parseRegexFromString` 直接识别 `/.../` 形式，大小写忽略通过末尾 `i` 标志控制）。
5. **次键限定语境**：主键「温泉」配合次键「旅行」与 `selectiveLogic: 0`（`AND_ANY`），可在旅行语境下精准唤起温泉旅馆条目。

## 三、递归设计

递归开启时（全局 `Recursive Scan` 启用），已激活条目 `content` 中的词语可继续触发其他条目。

| 目标场景 | 推荐配置 |
|---|---|
| 常驻总纲统领全局，保持按需绿灯安静待命 | `exclude_recursion: true` + `prevent_recursion: true` |
| 角色条目含关联人物姓名，仅在对话直接提及时出场 | `exclude_recursion: true` + `prevent_recursion: true` |
| 枢纽地点条目提到驻地角色时自动带出该角色 | 地点设 `prevent_recursion: false`，角色设 `prevent_recursion: true` |
| 幕后设定仅在其他条目引出后才浮现 | `delay_until_recursion` 设为 `1`（首轮递归入场）或对应递归层数 |

### 大型多角色卡实证配置

158 条实卡范本中，**77%（122 条）同时开启 `exclude_recursion: true` 与 `prevent_recursion: true`**。常驻基底与角色条目默认双向关闭递归，只给确需链式带出的地点或组织枢纽留单向出口，可稳妥守住上下文预算。

## 四、Inclusion Group（互斥组）

同 `group` 名称的多条条目同时命中时只注入一条：

- **随机风味事件池**：多条日常或氛围事件同组，按 `group_weight` 权重随机抽取一条。
- **状态确定性覆盖**：同一对象的不同状态同组，设 `group_override: true` 时按 `insertion_order` 最高者确定性胜出。
- **命中密度优先**：设 `use_group_scoring: true` 时，当前上下文命中关键词数量更多的条目优先注入。

## 五、Timed Effects（时效控制）

| 字段 | 机制效果 | 典型用途 |
|---|---|---|
| `sticky: N` | 激活后持续驻留 N 条消息，期间免除概率重判 | 场景或事件展开期间稳定在场 |
| `cooldown: N` | 驻留结束后冷却 N 条消息再开放触发 | 控制偶发氛围事件的出现间隔 |
| `delay: N` | 聊天累计满 N 条消息后开放触发 | 中后期自然解锁的设定或支线 |

组合示例：偶发风味事件设 `probability: 20` + `sticky: 4` + `cooldown: 10`，可呈现自然偶发、持续数轮后平息的节奏。

## 六、酒馆全局激活建议（随发布说明提示玩家）

| 全局设置 | 配置建议 |
|---|---|
| Scan Depth | 默认扫描最近数轮消息即可；特殊条目用条目级 `scan_depth` 单独指定 |
| **Match Whole Words** | **中日文卡保持关闭**，确保中文词组正常子串匹配 |
| Recursive Scan | 使用地点带出人物等递归链时开启 |
| Context % (Budget) | 大体量多角色卡建议适当调高上下文百分比预算 |

## 七、`content` 正文组织要点

- 顶层用 `<类型 name="实体名">` … `</类型>` 包裹（如 `<location name="区域名">` … `</location>`），清楚标示信息归属边界。
- 角色条目内部可直接放置完整的 `character:` 结构化 YAML，把台词样本收入 `dialogue_samples` / `chat_examples`。
- 每个条目保持单一归属与独立可读，与卡本体 `description.md` 及其他世界书条目各司其职。
- 中文约 1.5 字符折算 1 token，编写中文世界书时按实际 token 预算把控单条体量（常规单角色条目约 2k～8k token 即可立住丰满细节，留出同场多角色并存的预算余量）。

## 八、角色阶段、数值规则与阶段事件的独立条目设计

当角色随数值、关系或剧情产生跨阶段转变或触发关键事件时，**角色卡本体保留初始常态**；演进规则、各阶段面貌与单次事件分别拆为三类独立世界书条目：

### 1. 数值升降规则与阶段表（`rule` 条目，`constant: true`，`"@D2"` 或 `"@D0"`）

常驻注入，负责定义数值含义、单次波动幅度、加减分触发条件、双轨优先级，以及回复尾部的阶段锚点格式（代码块内保持纯净进卡文本）：

```xml
<rule name="角色_关系演进规则">
角色_关系演进系统:
  概述: 记录角色在相处过程中的信任与情感演进，初始值 1，上限 100，单次波动 0-5。
  双轨协调: 存在两条演进路线时，以当前活跃路线分值为准，当前阶段特征与语气优先于初始常态。
  阶段区间: 1-25 阶段一，26-50 阶段二，51-75 阶段三，76-100 阶段四。
  上升条件:
    - 情形: 贴合心意的互动或实质相助
      触发: {{user}} 做出契合角色看重原则的言行与选择
      波动值: "+2 ~ +4"
      说明: 角色感受到尊重或默契，防备随之松动
  回落条件:
    - 情形: 轻率冒犯或失信举动
      触发: {{user}} 触碰角色忌讳或敷衍应付
      波动值: "-1 ~ -3"
      说明: 角色重新拉起心理防线与相处距离
  尾部阶段锚点: |
    每轮回复末尾输出对应当前分值与阶段名的隐藏注释锚点：
    <!-- 角色_关系:<X/100 阶段一> -->
</rule>
```

### 2. 独立阶段条目（`module` 条目，每阶段一条，`constant: false`，`scan_depth: 1`，`"@D1"` 或 `"@D2"`）

- **触发配置**：主 `keys` 填对应阶段锚点名（如 `["阶段二"]`），`scan_depth: 1`（只扫描上一轮回复末尾的最新锚点，升阶后旧阶段自动卸载）。双轨并存时，低优轨设 `secondary_keys: ["高优轨阶段名"]` + `selectiveLogic: 2`（`NOT_ANY`）自动避让。
- **内容结构**：写明本阶段的 `阶段概述`、`心理与性格变化`（内在变化与外在表现）、`关系与核心行为`、`语言与台词参考`，以及正向的 **`当前阶段尺度与化解方式`**（交代本阶段互动停驻的自然分寸，以及对方超前试探时角色如何顺着性格转移话题、挡回或拉开距离）。

### 3. 单次阶段事件与同阶段分支（`event` / `plot` 条目，`constant: false`，`scan_depth: 1`）

- **单次结算事件（触发结算后自动退场）**：
  - 主 `keys` 填触发阶段或特定锚点（如 `["阶段四"]`），`secondary_keys` 填状态栏中代表事件已结算的状态词（如 `["关系状态A", "关系状态B"]`），`selectiveLogic: 2`（`NOT_ANY`）。
  - 刚步入阶段四且状态栏尚未更新结算状态时，条目在浅深度注入并引导事件发生；当轮结算更新状态栏后，下一轮自动命中 `NOT_ANY` 静默退场。
- **同阶段多路线分流**：
  - 各分支条目的主 `keys` 均填 `["阶段四"]`，`selectiveLogic: 0`（`AND_ANY`），各自的 `secondary_keys` 分别填入前置路线状态词（如 `["路线A"]` 与 `["路线B"]`），按前置选择自然分流。
