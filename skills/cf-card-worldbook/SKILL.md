# 世界书（v4.12.0）

范围：世界观写什么（世界节点），以及设定怎样变成按需加载的世界书条目。卡文件装配和导出校验不在本技能。

## 总规则

- **每步动笔前先写出明确判断**：在规划总纲、拆分子条目或改写设定前，先用两三句话写出明确判断，说明该设定在扮演中解决什么认知问题、哪些归入常驻硬锚点、哪些拆入下位按需绿灯并留出开放弹性，以及为什么这样切分。
- **先世界后角色**：世界总纲与下位条目拆分表在进入角色阶段前确认；`references/worldview-template.md` 提供参考骨架，动笔前先按当前卡提出结构提案，作者确认后再落笔。
- **区分硬锚点与开放方向**：正文用结构化自然 key（条目本名作 key，下一层按该事物的实际方面展开）：
  - **硬锚点与基本规矩（写实）**：时代地理、社会基本制度、客观结算条件（数值增减、品阶相生相克、阶段门槛、器物基础功用）、习俗与互动的标准步骤及边界。
  - **随境细节与概念留白（给开放方向）**：概念与氛围型法则（未知代价、认知异常、禁忌应验等）、日常风俗中的自然反应、不同人群的习惯与小心思、特殊场合变体，先写一句上位方向，再用 **「平时/通常……」「有时……」「一些人……还有一些人……例如……」「在特殊场合/特殊情况下……」** 给出代表性例子，让模型顺着世界逻辑现场发挥。
- **使用贴合世界观的本土自然语言**：概念名与方面名采用现成通用词或贴合时代背景的本土称呼；若设定原型带有现代二次元或外来标签词，正文中转化为契合本世界语境的本土名称，通俗叫法放入 `keys` 兼容触发。作者沟通时的比喻只提炼背后的条件、档位与限度。
- **条目独立自足**：每个条目激活时单独注入上下文，内容保持自包含，直接写清本条所需的规矩与范围。
- **按条目类型划分工程区域与三步任务方案**：

| 单元 | 前置判断与条目类型 | 只读范围 | 只写范围 | 写法与交付要求 |
|---|---|---|---|---|
| **Unit 1 上位世界总纲与拆分表** | 先写出常驻边界与上下位拆分判断；编写常驻蓝灯（`world` 基底与分支总纲、全局核心法则） | `记录/调研/00-索引.md`、`world-*.md` | `lorebooks/world/` 常驻总纲节点 + `记录/执行计划.md` 下位拆分表 | **平实说明文体（硬锚点写实）**：只放全线每轮通用的底子与各子类一句泛用定位 → **写完停下确认总纲与拆分** |
| **Unit 2 物种、专项机制与习俗** | 先写出概念性质与生理/功能边界判断；编写按需绿灯（`rule` / `lore` 物种生态、核心习俗、特殊机制） | 已确认总纲 + `记录/调研/rules-*.md` | `lorebooks/world/` 专项节点（每批 1～2 条） | **按事物属性定制说明文体**：硬规矩写实 + 开放方向举例 → **单批审阅调整** |
| **Unit 3 地点、器物、合集与全书联动核对** | 先写出触发路径与单点归属判断；编写按需绿灯（`location` / `item` / `wiki` / `plot` / `event`）并回查全书 | 已确认总纲 + 对应调研分包 | `lorebooks/world/` 地点、器物、合集与事件节点 | 补齐绿灯条目，核对 `keys`、双向防递归开关、常驻层零触发词泄漏与单点归属无遗漏 |

# 一、世界节点

## 用几层

题材来源在分诊时判定并确认：

| 题材来源 | 启用层级 |
|---|---|
| 原创世界 | `world_foundation` + `base_world`，有全线专属法则时加 `core_rules` |
| 已知作品正传 | `world_foundation` + `base_world`（熟悉背景适度精炼，决定世界运转的核心项完整保留） |
| 衍生 / IF / 特异二创 | `world_foundation` + `base_world` → `if_divergence` → `core_rules`，按基底到差分的顺序依次展开 |

各层职责：

- `base_world`：完整原作世界的常态面貌，涵盖 `world_history`、`world_location`、`core_systems`、`special_groups`、`social_structure`（自然环境特殊时补充 `environment_features`）。
- `if_divergence`：分叉点之后的变迁大势、新秩序、新势力与新据点。
- `core_rules`：全线生效的世界级规则，以法则本名作 key：
  - **客观结算型法则（连续梯度与双向开放）**：分方面写明触发条件、实际效果、作用限度与可逆条件；使用「当……时」「满足……或……条件时」等开放条件句，并用**连续梯度替代二值开关**（例如犯忌分「初犯轻忌环境示警留出补救窗口 → 再犯局部压迫反制 → 彻底撕破脸全面冲突」三阶缓冲；转化或收益分「激烈抗拒仅得一二成 → 半推半就或初步结契得四至六成 → 心神失守或深度动情自愿相托得八至十成」连续光谱）。全员适用的法则直接在适用范围写明「所有角色（包括 {{user}}）同受本规则约束」。
  - **概念与氛围型法则**：写清上位分类、触发方向与代价倾向，把具体应验形态留给现场推演。
  - **跨角色泛化博弈或认知规则**：与角色自身的 `personality`（性格、阅历、认知水平）及当前关系挂钩：
    1. 深浅随人：策略深浅由人物阅历与性格决定，老练者周密自然，生涩者易露破绽，率直单纯者按本心直来直去；
    2. 视角真实：角色基于自身性格与已知线索揣测他人意图，保留误判与试探空间；
    3. 开放示例：用「平时…有时…一些人…例如…在特殊情况下…」列举互动表现时，标明适配的性格类型。

## 上下位拆分与专项设计准则

1. **上位常驻泛用统领，下位绿灯单点归属**：
   - 常驻总纲（`constant: true`）使用纯泛用上位类别词（如「隐世宗门与民间异人」「不同渊源的异类族群」「实质交互或破除护体的成立条件」）统领全局，保持对具体角色名、具体地名、具体器物或支线专名的零引用，防止递归拉起下位绿灯或污染无关场景。
   - 当常驻条目需要移出具体专名或修改核心概念称谓时，先替换为通顺的上位泛用表述，并同步扫描所有常驻蓝灯与下位 `keys`，确保逻辑衔接严密且零泄漏。
2. **性质不同的概念物理独立成条**：
   - 成因、运作逻辑或触发场景截然不同的两个概念（例如两种不同体系的异常现象、两类性质相异的契约或场地），各自拆为独立的下位世界书条目，保持单条概念纯粹、触发精准。
3. **专项机制规则去剧本化（通用变量维度 vs 单人绝活分离）**：
   - **通用条目只写变量维度与原理**：技艺档位或对抗规则只界定底层阅历与控场能力边界（如懵懂本能、清白生涩、略通人事、熟稔控场、宗师收放），以及决定主导权消长的动态变量（造诣档位、精力充盈度、心神清明度、关系好感与器物克制），单人专属的小动作、部位习惯与独门道具一律退回对应 `character` 卡内；涉及主角侧的通用法门同样区分寻常生手之困与修习秘技者，保留普通开局的周旋张力。
   - **双向结果开放（稳控守成与动摇失守并存）**：涉及修持、试探、博弈或施救的规则，同时写明定力稳固或占优时的正向完成态（如恪守规矩稳控收功）与心神亏空或受克制时的失守态，由现场状态与互动方式实时裁定。
4. **按事物本性组织内容（物种 / 器物术法 / 习俗各司其职）**：
   - **特殊物种与群体条目**：合并呈现完整的客观生理硬件与泛用生态习性（无需把日常生理与亲密生理拆碎成两条），写清形体构造、感官特征、存续需求与先天习性；保持物种客观底线（如无呼吸心跳的异类保持相应生理静态），个体独门绝活归回对应角色的 `character` 条目。
   - **器物、法器与术法条目**：先立正统上位功能（日常、修行、防护、镇压或社交礼制中的本职用途与规矩），再将衍生妙用、私下变通或欢好助兴的特殊用法放入「有时…一些人…在特殊情况下…」的开放举例中。
   - **社会习俗与专门互动条目**：按「是什么与日常规矩 → 标准过程怎么做 → 常见细节与个体差异（有时…一些人…例如…） → 描写关注点」自然展开。
5. **多开局主角设定与能力弹性**：
   - 当卡片包含多条开局路线时，可将主角共用的体质底子或核心定位整合为单一开放的常驻说明（具体起点处境由各开局正文 `message/<序号>.md` 自然锚定），或将互斥开局背景设为按需绿灯 / `enabled: false`。主角核心能力写清原理与可用方向，留给玩家与剧情临场运用，避免写成死板的单向或双向自动结算公式。
6. **剥离与合并后的单点归属回查**：
   - 将原混在通用池里的单角色绝活、专属道具或身世细节剥离后，立即回查对应角色的 `character` 条目或专属绿灯，确认该设定已在唯一主归属处完整落位，做到既不跨层重复、也不遗漏丢失。

## 世界与角色的分界

- `world` 管客观地理、历史格局、自然与超自然法则、物种通性、社会秩序。
- `character` 管具体人物的身世、外貌、性格、口癖、个人绝活、私密反应与关系态度。人物在 `world` 中仅在必要时以某势力或历史事件的主导者身份客观带过一句。
- **视角与信息分层**：
  - 同一事件各人说法不一时，客观事实留 `world`，个人主观讲述归对应 `character`。
  - 存在认知信息差时，在常态条目加 `知情` 方面写明谁知晓到哪一层；核心隐秘真相单独放入默认关闭的揭晓条目（`enabled: false`），供剧情推进后开启。

## 节点元信息头（YAML Frontmatter）

`lorebooks/**/<条目>.md`（兼容旧目录名 `world_book/`）采用标准 YAML Frontmatter，下方直接书写带顶层 XML 标签的正文：

```markdown
---
id: wb-character-201
type: character
title: 角色                # 酒馆列表标题：非角色条目写自然名称；多角色卡的角色条可写「阵营 · 角色名」
keys: [本名, 称呼, 通俗名] # 触发词数组；常驻条目可省略 keys
secondary: []              # 二级过滤词
position: before_char      # 取值：before_char、after_char、"@D0" / "@D1" ...（带 @ 加双引号）
constant: false            # 常驻写 true；条件触发写 false 并配非空 keys
order: 201                 # 可省略交由导出按组连续编号，也可显式指定
---

<character name="角色">
...
</character>
```

- `type` 取值范围：`card`、`world`、`location`、`rule`、`item`、`lore`、`character`、`module`、`corpus`、`style`、`output`、`greeting`、`note`、`plot`、`wiki`、`event`。

# 二、世界书条目机制

依据 SillyTavern 源码枚举与大型多角色实卡范本核对。

## 核心规则

- **注入与命名**：`content` 注入提示词，`comment`（对应节点头 `title`）作为酒馆列表标题（100 字以内）。非角色条目 `title` 直接采用自然名称（与去掉数字前缀后的文件名及 `<标签 name="...">` 保持一致）；多角色卡的 `character` 条目可采用「阵营 · 角色名」，`<character name="角色名">` 保持本名。重命名文件时，同步更新 `title`、顶层标签 `name` 及跨条目关键词核对。
- **中日文匹配**：中日文卡在酒馆全局设置关闭 `Match Whole Words`，使子串关键词正常命中。
- **双向防递归默认开启**：所有常驻条目（`constant: true`）与多角色卡中的角色条目默认同时开启 `exclude_recursion: true` 与 `prevent_recursion: true`，阻断常驻总纲或角色关系链在首轮连锁拉起半本书；仅对确需链式带出的绿灯枢纽条目（如地点带出驻地人物）按需放开单向递归。

## 触发配置速查

| 场景需求 | 配置方式 |
|---|---|
| 全线底子常驻（世界总纲、全局硬规则） | `constant: true`，同时开启 `exclude_recursion: true` + `prevent_recursion: true` |
| 常规按需触发（角色、地点、器物、专项规则） | `constant: false`，`keys` 填入本名、简称、绰号与玩家常用通俗词 |
| 变体与多称呼紧凑匹配 | 将单个 key 写为 `/本名|别称/i` 正则形式（源码直接解析 `/.../` 语法） |
| 语境双保险（如特定氛围模块） | `keys` 写主词，`secondary_keys` 写语境词，`selectiveLogic: 0`（`AND_ANY`） |
| 角色跨阶段模块（每阶段独立一条 `module`） | `keys` 写最新阶段锚点名，设 `scan_depth: 1`（升阶后旧阶段自动卸载）；双轨并存时低优轨用 `secondary_keys` + `selectiveLogic: 2`（`NOT_ANY`）避让 |
| 单次阶段事件（`event`，结算后自动退场） | `keys` 写触发锚点，`secondary_keys` 写结算后的状态栏词，`selectiveLogic: 2`（`NOT_ANY`）+ `scan_depth: 1` |
| 同阶段分支分流 | `keys` 写同一阶段名，`secondary_keys` 分别写对应路线状态词，`selectiveLogic: 0`（`AND_ANY`） |
| 暂存备查条目 | 清空 `keys` 或设 `enabled: false` |

## 插入位置与分组编号

| 位置 | 适用内容 |
|---|---|
| `before_char`（↑Char） | 世界背景、地点、物种、角色档案等基础设定 |
| `after_char`（↓Char） | 补充交互法则、专项机制与文风指引 |
| `"@D4"` ～ `"@D0"`（@ Depth） | 贴近最新对话轮次的状态规则、阶段模块与输出校准（数字越小越贴近当前回复） |
| AN 顶 / 底（数值 2 / 3）、示例消息顶 / 底（数值 5 / 6）、Outlet（数值 7） | 特殊预设位或 `{{outlet::名}}` 宏调用位 |

- 新建卡按类型组连续编排 `insertion_order`：世界 `1xx`、人物 `2xx`、文风 `3xx`、输出 `4xx`、开场白及其他（`greeting / plot / event / wiki`）`5xx`；同一大类内按「上位总纲 → 同类下位专项」紧邻排列。
