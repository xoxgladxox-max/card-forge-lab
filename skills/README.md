# skills/：制卡领域技能集（9 个，cf- 前缀）

本目录保存各制卡技能的唯一源件。日常维护通过 `tt-card-bridge` 的 `tt-card skills` 执行版本核验、快照归档与多端同步（覆盖 Claude Code `~/.claude/skills/`、通用 Agent 目录 `~/.agents/skills/` 及本机扩展全局目录）；脱离本仓库单独分发时，也可直接复制单个技能文件夹到支持 Agent Skills 规范的宿主中使用。通用工具纪律与跨项目技能由宿主独立管理。

每个技能采用标准 Agent Skills 目录结构（独立文件夹 + `SKILL.md`），YAML Frontmatter 保持精简，仅包含 `name`、`description`、`metadata` 三个顶层键。

## 命名与版本规范

- **统一前缀**：自研制卡技能统一以 `cf-` 开头（card-forge），技能 `name` 与所在文件夹同名（小写英文字母加连字符）。部署工具依据 `cf-` 前缀识别管辖范围，保留目标目录中的其他第三方技能原样不动。
- **触发描述**：宿主依据 `description` 判断何时加载技能。`description` 以 `vX.Y.Z｜` 版本号开头，简明写清管辖职责与常见用户触发口令（用「」列出典型说法），详细规则放入正文。
- **模板定位**：技能内的结构模板作为起步基准，动笔前先写出针对当前题材的明确判断与结构提案，经作者确认后展开。酒馆卡底层协议（V2/V3 JSON 字段与 PNG 数据块）按导入标准严格执行。
- **三处版本号同步**：每次更新技能目录内的任意文件（含 `SKILL.md`、`references/`、`scripts/`）时，同步更新 `updated` 日期并保持以下三处版本号完全一致：
  1. `description` 首部：`description: v1.0.0｜...`
  2. `metadata.version`：
     ```yaml
     metadata:
       version: 1.0.0
       updated: YYYY-MM-DD
     ```
  3. 正文一级标题：`# 技能标题（v1.0.0）`
- **版本号递增规则**：措辞润色或勘误递增第三位（`1.0.0 → 1.0.1`）；新增规则、检查项、模块或参考示例递增第二位（`1.0.x → 1.1.0`）；调整既有职责边界、重命名核心结构或移除旧规则递增第一位（`1.x → 2.0.0`）。
- **快照归档与同步**：运行 `tt-card skills` 执行版本比对、历史快照归档与目标端部署；当内容变更未涨版本号或目标端存在更高版本时，部署工具会主动拦截提示，保护本机较新版本与不可变归档记录。

## 技能清单与职责分界

| 技能 | 领域 | 核心职责 |
|---|---|---|
| cf-card-research | 调研 | 多源检索、立绘全身读图、泛化事实判型与单次事件/原话语料物理分包、两原则一问题与缺口提问 |
| cf-card-worldbook | 世界书 | 常驻纯泛化世界基底与法则维度、下位条件绿灯具体风物/事件实例分离、条件触发替代比例排期、机制去剧本化与防递归配置 |
| cf-card-character | 角色 | 两原则一问题与预测输出方向确认、全场景泛化设定本体与独立条件绿灯语料/过往事件/亲密节点物理分离、开放可能性空间替代性格调色盘 |
| cf-card-review | 审查 | S1～S15 静态词句扫描与 C1～C30 语境深审（泛化与语料物理隔离、去比例盘与调色盘、防缺料脑补、跨层泄漏、隐藏标签正则）及上游归因 |
| cf-card-refine | 精炼 | 单一文本类型高密度正向改写、泛化层剥离原句与死动作、比例盘与调色盘转条件可能性、常驻词泛化替换 |
| cf-card-format-export | 配套与导出 | 宏观文风与肩扛镜头、语料声线校准与现场全新生成总控、五维反套路思维链、隐藏标签剥离正则、状态栏与导出校验 |
| cf-card-xiaobaix | 小白X前端 | 小白X（LittleWhiteBox）循环任务（`<<taskjs>>`）、交互界面、状态栏正则、变量同步与本地素材打包 |
| cf-card-oneclick | 一键出卡 | 第 0 步提问补齐缺口并确认体验方向与预测输出方向，串联调研至装配全链路执行两原则一问题与泛化/语料分离 |
| cf-card-project | 卡工程 | 一级卡工程目录分区（含泛化本体与条件语料绿灯分区）、多开局与隐藏标签正则归档、改名全书同步与酒馆拆装推拉 |

**独立解耦原则**：各领域技能与 `cf-card-project` 均自包含独立运行，互不点名其他兄弟技能；全链路编排顺序集中在 `cf-card-oneclick` 中定义。通用元规则置于全局 System Prompt。

## 发布前核验

公开提交前执行全量扫描：确认无密钥凭据、无私人卡设定专名、无本机个人绝对路径、无 UTF-8 BOM 头，且全部技能三处版本号一致、测试全绿。
