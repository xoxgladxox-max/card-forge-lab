# skills/：我们自己的技能（8 个，cf- 前缀）

这里是技能原件，只保留一份。可以手工复制到所用 AI 工具的技能目录，也可以用 tt-card-bridge 同步到 Claude Code（`~/.claude/skills/`）、Codex 等通用目录（`~/.agents/skills/`）和酒馆。通用工具纪律、思考辅助和其他项目的技能由宿主管理，不放在这里。

每个技能都是通用的 Agent Skills 格式（文件夹 + `SKILL.md`，开头只有 `name`、`description`、`metadata`），单独拷走一个文件夹就能在支持这种格式的工具里用。

## 命名与版本

- **前缀**：我们自己写的技能一律以 `cf-` 开头（card-forge）；第三方技能保持原名，不进本仓库。技能 ID 按目录名生成，`name` 字段必须与目录名一致。部署工具靠这个前缀认自己的技能，不碰目标目录里的第三方技能。
- **触发**：宿主靠 `description` 决定什么时候加载。description 写「管什么 + 用户会怎么说」，把常用说法用「」列出来；格式细节写进正文，不占 description。名字只能用小写英文和连字符，要一眼看出管什么。
- **模板是示例**：各技能里的模板只是起点。动笔前先按这张卡提出结构提案，作者确认后再写。酒馆卡文件格式（V2/V3 字段、PNG 数据块）是导入要求，不算示例。
- **版本号**：写在 SKILL.md 开头信息的 `metadata` 下（多数宿主只读取 `name` 与 `description`，其余行忽略；`metadata` 下不要写 `name:`）：

  ```yaml
  metadata:
    version: 1.0.0
    updated: YYYY-MM-DD
  ```

- **怎么涨**：措辞修正、错别字 → 第三位（1.0.0 → 1.0.1）；新增规则、检查项、模板 → 第二位（1.0.x → 1.1.0）；改变已有规则的意思、改名、删规则 → 第一位（1.x → 2.0.0）。技能目录里任何文件改动（含 references、scripts）都要涨，并同步改 `updated`。
- **存档与部署**：用 tt-card-bridge 的 `tt-card skills`，不要手工复制。内容改了但版本号没涨、或目标上的版本比仓库新，部署会拒绝。存档后的版本不可修改；回档后版本号自动加一。

## 清单与职责

按领域划分：

| 技能 | 领域 | 职责 |
|---|---|---|
| cf-card-research | 调研 | 查资料、来源分级、交叉核对、搜索渠道与深度搜索、PDB 判型 |
| cf-card-worldbook | 世界书 | 世界节点（worldview_profile、三层世界、世界与角色分界）和世界书条目机制 |
| cf-card-character | 角色 | 角色本体、附加模块、语料：字段、档位、关口 |
| cf-card-review | 审查 | 成文检查：静态规则和语境规则 |
| cf-card-refine | 精炼 | 条目改成自定义 key 加方面机制；角色设定从上位概念逐层收窄；删不起作用的句子 |
| cf-card-format-export | 配套 | 文风、回复格式与状态栏、开场白，以及装配导出（字段去向、卡格式、PNG、校验脚本） |
| cf-card-oneclick | 一键出卡 | 开头一次确认需要什么和结构提案，然后按 调研 → 世界书 → 角色 → 配套 → 审查 → 装配 自动跑完 |
| cf-card-project | 卡工程 | 卡工程的位置、分区、认版本，以及接卡、推送、拉回流程；具体命令只在文末「工具对照」里举例 |

**独立原则**：领域技能和 cf-card-project 单独加载就能完成自己的事，不点名别的技能。只有 cf-card-oneclick 说明各领域的调用顺序。元规则和写卡规则放在全局 System Prompt 里，不在任何技能里点名。
