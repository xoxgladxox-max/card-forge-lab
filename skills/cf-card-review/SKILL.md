# cf-card-review：成文检查规则集

## 什么时候必须调用

- **写卡前**：资料已经足够、准备从素材进入成卡前，先调用本 skill 做一次“缺口与方向检查”。资料明显不足时先停，不用检查把未知内容填满。
- **写卡中**：每完成一个大模块，按需复查；新增设定、改动核心性格、调整关系或拆分世界书条目时重新检查受影响部分。
- **定稿前**：必须全量检查 S 组与 C 组；未通过不得称为定稿。
- **跑卡中**：发现复读、角色跑偏、设定不生效或状态栏过载时，先把问题归因到文本、结构、触发机制或模型表现，再决定改哪一层。

## 检查本质：从上到下定范围，从下往上验归属

1. **先找上位概念**：这条内容属于人格、外貌、语言、关系、世界规则、地点、角色、事件、状态还是成人模块？
2. **再定关键词与 tag**：作者到底想让模型偏向哪个方向？只保留作者确认过的方向，不把标签的常见联想自动当成设定。
3. **最后下钻到具体细节**：只补确实想锁定、且能被正文调用的语言、动作、选择、限制或结果。越往下写，生成倾向越集中，可保留的可能越少。
4. **反向复查**：具体细节是否属于上位概念？是否增加新信息？是否有资料或作者意图？是否只是近义重复？是否把开放倾向写成固定流程？
5. **检查归属和重复**：同一内容可以跨容器出现，但每处必须承担不同功能；对特定对象成立的内容归关系，对全局成立的内容归全局块，不为了形式抹掉关系信息。
6. **检查概念作用**：每个设定至少改变语言、行为、选择、关系、场景或可追踪状态之一；没有实际作用的名词、字段和细节删除。

上位概念、关键词、tag 是整理和审查顺序，不是必须新增到最终卡或世界书的字段。检查的目标不是把概念树分得漂亮，而是确认每次向下细化都有意、有效、有依据，并且没有误锁作者想保留的开放范围。

## 检查报告格式

每轮只报差异，不重贴全文：

```text
本轮查项：
问题 N 处：
- 位置：
- 问题：
- before → after：
存疑待裁决：
通过条件：
```

- `before → after` 只在已经获准修改时填写；需要作者决定的内容放入“存疑待裁决”，不擅自改稿。
- 区分“缺资料”“归属错误”“重复注水”“过度收窄”“固定流程”“技术失效”“模型表现偏差”和“上游缺陷”，不要统称为写得不好。
- **上游缺陷**：正文的错来自规划、结构、料源索引、模版、任务书或验收本身（例：C11 命中通常是结构里就没给原作基底留位置、料源索引里就没有基底料）。报告写明最高出错层，交回上游处理，不给正文 before → after。
- 检查是内审，不要求作者重读全文；只列问题和必要 diff。

## S 组：静态规则（纯文本搜索即可判定）

| 编号 | 规则 | 检法 |
|---|---|---|
| S1 | 外语残留 | 输出语言为中文时，搜 ちゃん/です/ます/さん/くん 及整句外语；歌名与专有名词豁免 |
| S2 | 机械八股词 | 搜「机械」「拉扯」「张力」「撕裂」；规则文本中改「死板照抄」，正文中改具体动作 |
| S3 | 电报体成行 | 搜独立成段的 ≤6 字短句（「截然相反。」「线索彻底断了。」类）；并入长句 |
| S4 | 廉价通感隐喻 | 搜 糖/蜜/毒 作喻体的句子 |
| S5 | 心理学后设术语 | 搜 斯德哥尔摩/PUA/煤气灯/操纵/人设面具/假面 等学术与后设词 |
| S6 | AI 八股生理反应 | 搜 瞳孔收缩/瞳孔骤缩/指甲嵌进掌心/胃袋失重/喉结滚动 |
| S7 | 口癖复用 | 同一输出内「微微」≥3 次、同一小动作（摸口袋等）≥2 次、同一道具场景复用 |
| S8 | 空洞程度词 | 搜 要/很/比较/有点 修饰的形容词（卡文本适用），换可执行行为 |
| S9 | 保守回避词 | NSFW 块内搜「安全裤」等回避性替代词 |
| S10 | 世界书关键词泄漏 | 正文中搜当前卡世界书的触发词与条目内部术语原文 |
| S11 | 财务与说明文腔 | 搜 账本/记账/欠账/收支/债务 及医学、统计、报告式措辞；场景本身设在该领域时豁免 |
| S12 | 世界节点角色痕迹 | 只扫世界、地点、规则、背景这类设定的正文：搜本卡各角色的名字与关键词，以及 穿越/身世/出身/性格/喜欢/讨厌/口癖/战力/数值/面板/好感/心理 等个人向字样；命中只做标记，逐条交 C12 判 |

**检法通则**：S 组命中后先看上下文再报。三类必须豁免：① 禁令句本身（「严禁使用糖/蜜/毒」「严禁机械照抄」这类句子不是违规）；② 专有名词与原作设定（「机械熊耳头饰」）；③ 描述注意力去向的合规词（「倾向呈现」「会」）——这些不在任何黑名单里。裸字符串匹配不区分「用这个词」和「禁这个词」，直接报就是误伤。

## 检查顺序与边界

先自上而下核对规则层级、当前阶段、对象/字段与证据准入，再按当前字段规则检查正文；局部一致性检查不能推翻上层裁定。看不到料源或作者裁决时，不擅自判定事实真假，列为待核并停止该细节进入卡。一处局部无据只影响该细节及可证明受影响的内容，不扩大否定范围。操作成功或格式通过不等于内容逻辑通过。

## C 组：语境规则（需读上下文判断）

| 编号 | 规则 | 判据 |
|---|---|---|
| C1 | 代写 {{user}} | 是否写了 {{user}} 的心理、推理、决策、连续台词；有则删，改为 {{char}} 可观察到的言行 |
| C2 | 上帝视角拆解 | 是否用叙述者口吻直接解说人物动机机制；改为落到具体言行让读者自行推断 |
| C3 | 推理空间写死 | 悬念是否被当轮解答完；应只留触点 |
| C4 | 称呼/语体档位 | 若卡定义了多档自称或语体（如公开场合与私密场合不同），是否与场景匹配 |
| C5 | boundaries 违例 | 是否出现违反当前卡角色 boundaries 声明的行为 |
| C6 | 节奏跳级 | 冲突/亲密强度是否跳过铺垫直达高强度（含特化块声明的分级门槛） |
| C7 | 结尾越权 | 末段是否替 {{user}} 接话或预设其反应 |
| C8 | 静默渗漏 | 特化文风块未激活时其词汇、话术、癖好倾向是否渗入 |
| C9 | 信息倾倒 | 配角是否像复述世界书条目一样工整倒设定 |
| C10 | 数值无因果 | 状态栏数值变动是否有正文事件支撑 |
| C11 | 基底立足度 | 已有作品衍生/IF/特异题材：把世界设定里属于分支改动和本线独有规则的部分全部遮掉，剩下的能否撑起一个原作世界的普通日常场景？地理格局、运转法则、核心物种（不止分支里出场的那一种）与常态社会有缺项就不过。按「上游缺陷」归因 |
| C12 | 世界越界写角色 | 世界、地点、规则、背景设定里出现的角色，是否只是以势力或事件主导者的身份被一句客观带过？写了个人身世、面板、性格好恶、私密互动的，就是越界：内容移到对应角色的设定里，世界设定里只留势力或事件那一句。反向同查：角色设定是否在复述世界法则 |
| C13 | 开场白前提无出处 | 开场白里交代的处境、起因、身体状态、时间压力等前提，是否每条都能在原作或已确认的设定里找到出处？找不到就是编造：改成开放写法（例：「送来得比平常晚」，不定死原因），也不替 {{user}} 预设剧情走向 |
| C14 | 句式在一组条目里复现 | 同一组条目（配角群、同层地点）里，同一个句子骨架是否反复出现（例：「某人不知道 X」出现多次）？卡里或全局写明的禁用句式清单，每写完一条就拿来扫一遍正文，不等定稿才扫 |
| C17 | 事实依据与准入 | 每条原作事实能否回到具体料源或作者明确确认？旧卡只作线索、不作证据；无正向依据就不写入卡，不要求先证明原作绝对不存在。看不到来源时列待核并停止该细节，不自行断言真伪 |
| C18 | 纠错范围不过界 | 是否只改已确认的具体错误及其可证影响范围？保留独立有据、已确认且不受影响的内容；不因一个形态/字段无据就否定其他形态/字段或整块。重开已确认节点先得作者同意 |
| C16 | 秘密与暗示 | 角色卡和常驻条目里有没有「隐瞒」「另有身份」「真相是」「实际上」这类把秘密推到模型眼前的写法？秘密只写一处、放默认关闭条目；角色不知道的事，卡里就不出现。规则改动后先按新规则审一遍所有常驻条目 |
| C15 | 同时加载能分清 | 几条同类条目（几个地点、几个配角、几套文风）同时加载时，只看正文能否分清各是谁、哪儿？包裹的 name、part 与标题要对得上；先跑 `check`，P18 系列无警告再读正文 |
| C19 | 通用槽位与空话 | 条目是否套了 `name` / `definition` / `description` 这类固定槽位，而不是用条目名和它自己的方面名作 key？定义是否只是把名字换个说法？描述是否只讲往事、对当下没有作用？逐句问「删掉它，玩卡时写出的内容会不会变」，不会变的标出。按「重复注水」归类；改法是条目名作 key、分方面写条件与结果，数值、限度、例外不删 |
| C20 | 写卡备忘留在正文 | 正文里有没有写给写卡人看的取舍说明（「不用某某的推测」「按某卷的说法」「以官方为准」「旧稿写错已改」「待确认」、`*_guide` 这类字段）？模型不知道它指什么。挪到 `## 工序` 或 `note/`，正文只写备忘背后的结论；人物的猜测对扮演有用时，写进该人物节点并标【角色说法】 |

## 资源

- `references/banned-words.md`：词汇黑名单原文（行业腔、说明书腔、后设词等），S 组各条的完整词表在此；S 组只列检法，词表不复制进本文。

## 使用

- 跑卡：writer 每段自查 S 组重点 + C1/C7；linter 全量扫两组。
- 写卡：资料确认后、成卡前先做缺口与方向检查；审查阶段与终检阶段全量扫。
- 世界书：本 skill 只查文字；JSON 字段、触发、递归、位置和深度属于机制校验，另做，不混成一关。
- 新病灶入库：任何一次终审发现的新问题，以「编号 + 规则 + 检法」格式追加，不写案例长文。
