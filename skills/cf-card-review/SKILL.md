# 成文检查规则集（v2.18.0）

## 总规则

- **每报一处问题先写出明确诊断判断**：指出问题前，先用一两句话写出明确判断，说明这处写法在扮演中会造成什么实际后果（如触发递归污染、粉红大象效应诱导坏词、把路径锁成单一死胡同或让角色脱戏），并标明最早出错的上游层级。
- **文本逻辑与工程机制协同分查**：本技能负责文本内容、概念归属与语境逻辑检查；JSON 字段、递归开关与分组编号由世界书与协议校验脚本配合完成。
- **有据核实与最小纠偏范围**：以原始料源与作者确认事项为准，资料待补处标为待核并暂停进卡；修订聚焦具体问题及其关联影响范围，完整保护其余已确认内容。
- **区域划分与两级检查方案**：
  - **只读范围**：待检模块或全卡节点、`src/lib/lint-rules.mjs`；**只写范围**：`<卡名>/记录/审查报告.md`（获作者确认后再进入修改环节）。
  - **Unit 1 单模块即时检查（按文体对口检查）**：
    - **世界书与角色设定块（说明文体）**：重点核查 S10–S12、S15、C12（上下位单点归属与剥离回查）、C19（空话与虚空防御）、C21–C23（比喻剥离、现成词、锚点弹性与排他词松绑）、C27（生理功能边界与多维表里）。
    - **角色台词与语料块（口语文体）**：重点核查 S1、S6、S7、C4、C28（口语纯粹度、自然语气词与日常台词知情范围）。
    - **文风、总控与开场白（规则协议 / RP 正文）**：重点核查 S1–S15、C1–C7、C13、C23–C26（四级镜头、潜台词性格区分、末尾正文语态）。
  - **Unit 2 全卡终审与上游归因**：交付前全量运行 S1–S15 与 C1–C28，定位问题源头层级（规划 / 节点拆分 / 调研 / 模板 / 正文）。

## 检查时机

| 时机 | 检查重点 |
|---|---|
| 写卡前（调研收束后） | 核对核心体验锚点、基底完整度与资料【缺口】 |
| 写卡中（每完成一个独立单元） | 按当前单元文体即时核查主归属、常驻零泄漏与开放弹性 |
| 交付前终审 | 全量运行 S 组与 C 组，核对跨文件同步与单点归属无遗漏 |
| 跑卡调优时 | 区分问题源自提示词文本、世界书触发配置还是模型采样表现，回到对应源头调整 |

## 报告格式

按差异输出精炼报告：

```text
本轮查项：
问题 N 处：
- 位置：
- 明确判断（会导致扮演模型产出什么毛病 / 源头在哪一层）：
- 修订建议（已获准修改时给 before → after）：
待作者确认项：
通过条件：
```

## S 组：静态规则（文本搜索可定位，词表见 `references/banned-words.md`）

| 编号 | 规则 | 检法与处理 |
|---|---|---|
| S1 | 外语残留 | 中文输出中搜 `ちゃん/です/ます/さん/くん` 及整句外文；作品专名与曲名豁免 |
| S2 | 机械八股词 | 搜「机械」「拉扯」「张力」「撕裂」；规则中改为直观行为描述，正文中改为具体动作 |
| S3 | 电报体短句成行 | 搜连续独立成段的极短句；融入连贯的环境光影与动作长句 |
| S4 | 廉价通感隐喻 | 搜以「糖 / 蜜 / 毒」作陈旧喻体的句子，改为真实感官描写 |
| S5 | 心理学后设词 | 搜「斯德哥尔摩 / PUA / 煤气灯 / 人设面具 / 假面」等场外标签，改为具体言行 |
| S6 | AI 套路生理反应 | 搜「瞳孔骤缩 / 指甲嵌进掌心 / 胃袋失重 / 喉结滚动」，换为贴合人物的真实反应 |
| S7 | 口癖与动作复读 | 同一段内高频副词（「微微」≥3 次）或同一习惯小动作反复刷屏 |
| S8 | 空洞程度副词 | 卡内设定搜「要 / 很 / 比较 / 有点 + 形容词」，落实为可观察的具体行为 |
| S9 | 保守回避词 | R18 模块内搜生硬回避词，保持直白准确的自然词汇 |
| S10 | 常驻层绿灯触发词泄漏 | 扫描 `description.md`、常驻 `world / rule / style / output`、`<thinking>` 与开场白，核对是否出现下位绿灯条目的 `keys`、具体角色名或代码字段名（配合 `P25` 拦截） |
| S11 | 跨行业账本与报告腔 | 搜非本行业的「账本 / 清算 / 资产 / 回路 / 机制 / 参数」等错位行话 |
| S12 | 世界节点夹带个人痕迹 | 非角色条目中搜具体人物名及「身世 / 性格 / 喜欢 / 讨厌 / 好感」等个体词，交 C12 复核 |
| S13 | AI 抒情套话 | 搜「不禁 / 油然而生 / 仿佛 / 宛如 / 这一刻 / 值得注意的是」，改为客观白描 |
| S14 | 「的」字堆叠 | 正文单句连续嵌套三个以上「的」或「的的」，重组修饰语序 |
| S15 | 凭空否定对比句 | 搜无前文铺垫的「不是 A，而是 B」「并非 A，实则 B」，直接正面陈述是什么 |

上下文豁免：作品固有专名（如「机械熊耳头饰」）与自然表达注意力倾向的词（「平时倾向」「有时会」）正常保留。

## C 组：语境规则（结合上下文判断）

| 编号 | 规则 | 判据 |
|---|---|---|
| C1 | 代写 {{user}} 与情绪越权 | 检查文风说明与正文是否替 {{user}} 写出台词、后续动作、心理决定，或越权规定主观情绪定论（如要求“强调 {{user}} 的紧张感或被支配感”）；应只写逼向 {{user}} 的外部感官信号，将情绪定义权留给玩家 |
| C2 | 取景框越界、初见报菜名与说明书台词 | 检查是否跨出当前跟拍镜头取景框与知情范围（写出遮挡物内部、未知前史、未暴露底牌），是否在角色远中距初登场时罗列全身内衬纽扣显微清单，或借角色台词背诵设定条款 |
| C3 | 悬念单轮写透 | 悬念与伏笔只呈现可察觉的蛛丝马迹，把谜底留给后续互动揭开 |
| C4 | 称呼与自称档位 | 核对不同公开或私下场合的自称、称呼是否与角色 `speaking_style` 一致 |
| C5 | 角色舒适底线 | 核对互动是否契合角色当前的阶段尺度与底线设定 |
| C6 | 铺垫与层级平滑度 | 冲突或亲密升温是否具备合理的环境与情绪铺垫，遵循相邻镜头层级自然过渡 |
| C7 | 收尾留扣干净度 | 回复末尾是否停在等待 {{user}} 回应的具体动作或问话上，省去画蛇添足的总结引导句 |
| C8 | 特化模块启停边界 | 特化文风或亲密模块未达启用条件时保持静默，退出后回归常态语感 |
| C9 | 配角自然对话 | 配角言谈贴合自身处境与眼界，避免充当设定讲解员 |
| C10 | 状态栏因果支撑、防剧透与初见锚定 | 状态栏每项变化须有当轮正文事件呼应；核查初始 `<status>` 是否提前剧透未揭晓的暗袋底牌（应以泛用词留白），以及初见陌生人物的初始关系是否合理锚定在 `0 ~ 15` 区间（受执念规则强行认亲者须注明属单向执念投射） |
| C11 | 原作基底完整度 | 衍生或 IF 题材遮去分支改动后，地理、核心系统、主要物种与常态社会仍能稳妥支撑日常戏；缺失时归入上游结构补齐 |
| C12 | 上下位单点归属与剥离回查 | 常驻层（`description.md`、常驻 `world / rule / style / output`）保持纯上位泛用词统领（移出专名前先用上位泛用词替换，改名时全书同步）；具体原理与局部物种归下位绿灯，个人表现与独门绝活归对应 `character`。**同查剥离回查**：从通用池剥离单角色绝活或合并条目后，逐一确认对应角色或下位条目已完整承接，确保零重复且零遗漏 |
| C13 | 开场白初见景深对齐与前提留白 | 核查开场白初见镜头是否贴合全景/中距景深（抓光影轮廓与 2～3 处核心视觉锚点，避免粘贴全身穿搭说明书）；异常与处境有出处则写准，无定论则只写现象、留白成因 |
| C14 | 同组条目句式多样化 | 检查配角群或同组地点条目是否套用同一句式模板机械复写 |
| C15 | 多条并存清晰可辨 | 多条同类绿灯同时激活时，`title`、顶层包裹 `<标签 name="..." part="...">` 清晰对应（配合 `P18` 系列核验） |
| C16 | 隐秘真相隔离存储 | 常驻与常态角色卡保持表面认知，核心隐秘真相单独放入默认关闭的揭晓条目（`enabled: false`） |
| C17 | 料源与确认依据 | 原作事实可回溯至料源或作者确认，推断标明提案，未知标明【缺口】 |
| C18 | 修订边界精准 | 修改聚焦于确证问题及关联范围，完整保留已确认的模块与独立设定 |
| C19 | 去除空话、指路语与虚空防御 | 检查是否套用空洞的 `name / definition` 槽位、跨条目指路废话（「详见某绿灯条目」），以及**虚空防御句**（旧稿问题删净后仍残留的靶向纠偏禁令、低概率错码禁令或防御性否定口号等引偏注意力的冗余话术），将有效要求直接写为正面做法 |
| C20 | 写卡备忘归档记录 | 正文中的取舍备忘（「按某卷写」「旧稿已改」）移入 `记录/决策记录.md`，正文只留干净结论 |
| C21 | 场外比喻转化为机制 | 作者沟通中的现代类比提炼为客观条件、档位与限度；现成概念与圈内通用 tag 直接保留 |
| C22 | 现成概念替代生造词 | 检查自造四字词、句内双破折号与句尾贴标括号，改为现成 tag 或通顺的条件陈述句；现代外来标签词在古风或本土世界观正文中转化为契合语境的本土名称，通俗词放入 `keys` |
| C23 | 本我内核、可能性空间与排他词松绑 | 核对角色卡是否区分「本我内核硬锚点」与「语料库可能性空间」（随境变体先立上位原则再用「平时…有时…一些…例如…在特殊情况下…」采样，并在 `roleplay_tips` 声明随现场自由演化）。**专项排查排他限定句**：排查锁死单一前置条件的封闭句式，除真正唯一的底线外，全部松绑为开放条件句，并核查性质相异的概念是否已物理拆分为独立条目 |
| C24 | 四级双轴镜头与潜台词性格适配 | 核对宏观与微观文风分层、四级颗粒度（全景 / 中距 / 近距 / 微观）平滑缩放与单点归属；检查对白规则是否区分了「设局者留白」与「坦率者直言 / 害羞或遮掩者借口粉饰」，避免一刀切封杀解释性台词导致角色失语 |
| C25 | 角色知情范围同步 | 核对存在信息差的设定是否写明 `知情` 层次，人物言行严格贴合自身已知线索 |
| C26 | 基准样例段、中立反套路思维链与双通道正则 | 核对宏观文风块末是否附有正文语态样例段；若启用显式 `<thinking>`，核查是否保持 5 行以内的中立思考维度与反套路推演（清除预填固定战术剧本与旧句默写清单），且已在 `regex/` 配套 `markdownOnly: true` + `promptOnly: true` 双通道剥离脚本 |
| C27 | 机制去剧本化、连续梯度与同档位差异化 | 检查通用机制条目是否剥离了单人分镜小动作与默认主角宗师预设，是否做到了双向结果开放（稳控守成与动摇失守并存）并用连续梯度（三阶缓冲）替代二值开关；核查角色日常块常态净室边界，以及同一技艺档位下的不同角色是否从各自的本我认知与执念生长出截然不同的互动表现 |
| C28 | 台词口语纯粹度与防报菜名剧透 | 检查 `dialogue_samples` 是否保持纯口语、使用自然中文语气词；确认角色随口双关戏称留在口语层未升格为硬专名，且日常闲聊台词聚焦眼前人事，未提前点名剧透尚未登场的其他角色 |
