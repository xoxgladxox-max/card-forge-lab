# 调研（v1.10.0）

范围：负责资料抓取、多源交叉核实、研究者判断输出与缺口清单整理，为下游制卡环节提供可追溯的原始素材与事实边界。

总规则：

- **每步整理前先写出研究者主动判断**：在 `00-索引.md` 与各分包文档中显式设立「研究者判断」段，主动评估三件事：一是**来源可靠度权重**（原作一手正文与官方立绘优先，官方访谈与章末附言次之，多语言百科共识再次，孤立二手词条与个人长评仅作线索）；二是**冲突证据的取舍理由**（指明采信哪一方或并列存疑的原因）；三是**本我实锤边界与可能性留白**（划清哪些属于角色的底层身份、静态生理硬件、核心执念等硬锚点，哪些属于单次情境下的台词动作采样或原作留白，留白处如实标注待作者决定）。
- 抓到的网页原文、JSON 与图片当场归档进工程目录，后续引用直接指向归档路径。
- 每条事实标明出处与说话者；旧草稿作为检索线索使用，经一手或多源核实后列入事实。
- 检索未命中时如实记录为「本轮检索未命中」及已查范围，与「原作明确无此设定」区分表述。
- 研究者的推断与补全方案统一标为【提案】，经作者确认后再转入下游设计。

# 工程区域划分与分模块方案

调研涵盖四类不同性质的材料：原始抓取归档、客观事实考据、人格类型专业分析、角色原话口语台词。按文本类型分文件独立存放，保持各分包文体纯粹：

## 1. 按文本与资料类型划分工程区域（写入 `记录/调研/` 与 `_web/`）

| 区域名称 | 物理路径 | 文本/资料类型 | 语言与文体要求 | 下游消费环节 |
|---|---|---|---|---|
| **总目录与缺口区** | `记录/调研/00-索引.md` | 索引清单、研究者总判断与待定表 | 简明条目，列出分包路径、来源权重判断、已确认范围与【缺口】 | 全流程先读 |
| **原始网页与立绘区** | `_web/out/`、`_web/<角色>/` | 原始 HTML / JSON / 立绘图 | 原样保存抓取结果与图片文件 | 核查原句或读图时读取 |
| **世界基底考据区** | `记录/调研/world-<主题>.md` | 客观事实整理 | 平实客观的事实陈述 + 来源标注 + 边界判断 | 下游世界基底构建 |
| **机制与道具考据区** | `记录/调研/rules-<主题>.md` | 规则与事件考据 | 触发条件、过程梯度、双向结果与例外的客观记录 + 来源标注 | 下游规则与器物构建 |
| **单角色事实与判型区** | `记录/调研/char-<角色名>-档案与判型.md` | 客观经历 + 专业类型学分析 | 经历与全身视觉锚点写客观事实；MBTI / 九型 / 本能副型使用认知功能、侧翼、主导本能等准确专业术语分析 | 下游角色本我内核构建 |
| **单角色原话语料区** | `记录/调研/char-<角色名>-台词语料.md` | 纯人物原话口语 | 原作台词原句、自称、对人称呼、口癖、句尾语气与口头戏称，保持纯粹人物口语 | 下游角色语料与声纹采样 |

## 2. 四步独立执行单元（单次运行一个单元，完成后停下交付）

- **Unit 1 调研方向与分包清单确认**：确认查证对象、体验 key 与已有材料，建立 `记录/调研/00-索引.md` 并写出初步渠道判断后**停下等作者确认**。
- **Unit 2 世界与规则考据**：抓取并交叉核实世界背景与机制规则，区分客观专名与人物口语修辞，写入 `world-*.md` 与 `rules-*.md`，更新 `00-索引.md` 后**停下交付**。
- **Unit 3 单角色档案与人格判型**：每次聚焦 1 名角色，下载立绘读图提取全身客观视觉细节，拉取百科与 PDB 数据推导认知功能与九型，写入 `char-<角色名>-档案与判型.md` 后**停下交付**。
- **Unit 4 单角色原话台词语料**：每次聚焦 1 名角色，采集不同情境下的原作台词原话、称呼变化与口头戏称（达到隐去署名仍可辨识说话人的颗粒度），写入 `char-<角色名>-台词语料.md` 后**停下交付**。

# 来源准入与性质辨析

整理每条材料前，先判定其文本性质：原作直接呈现的客观事实、特定角色或叙述者的主观说法、口语戏称与修辞比喻、作者场外补充、研究者推导或留白未知。

- **区分口语戏称与客观设定专名**：核对词语时结合语境判断其层级。全作通用的制度、地理、物种、器物与能力体系归入 `world-*.md` / `rules-*.md`；角色在对话里的外号、夸张吐槽、自嘲、私人暗语或临时比喻（例如把普通活动室戏称为「作战本部」、把严厉前辈戏称为「大魔王」），注明说话者与语境归入该角色的 `char-<角色名>-台词语料.md` 或关系印象段，保持世界设定的客观纯净。
- **保留多视角分歧**：不同角色对同一事件的叙述存在出入时，分别标明说话者归属并原样保留；客观事实层只写多源证实的交集，原作有意留白处直接标注留白。
- **局部存疑局部隔离**：单一细节缺乏材料支持时，将该细节单独标入【缺口】，其余已证实字段照常整理。
- **原文与正文优先**：事实核对以作品原始语言正文为最高依据；章末附言、访谈与活动报告作为补充参考，若与正文出入则以正文为准并在判断栏记录差异。参考译文理解大意后，涉及主语、人称指代与归属关系时回查原文核实。
- **审查反馈回查原文**：收到外部或下游提出的「查无原句」「设定出入」意见时，回到归档原文核对具体行号，附上原句行号给出采纳或维持原判的依据。

# 网页抓取：本机 Chrome Headless

遇到站点开启 Cloudflare 质询或前端动态渲染时，调用本机 Chrome headless 一次完成渲染与正文提取：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/fetch.ps1 -Url "<网址>" -Out "<输出基名>"
```

- 产出 `<输出基名>.html`（完整 DOM）与 `<输出基名>.txt`（去标签正文）；命中验证页或正文过短时输出 WARN，异常返回退出码 1。
- 可选参数：`-Budget` 控制渲染等待毫秒数，`-TimeoutSec` 控制超时秒数，`-Chrome` 指定浏览器路径，`-Profile` 指定持久化目录以复用 cookie。
- PowerShell 5.1 调用 `Start-Process` 时，对含空格的 `--user-agent=`、`--user-data-dir=` 与 URL 显式包裹双引号。
- 遇到需人工点击的验证页时，加 `-Headed` 弹出窗口完成一次验证，cookie 写入持久化 profile 后即可恢复 headless 批量抓取。

# 立绘与全身视觉考据

- **直接读图提取视觉事实**：按「官方立绘与设定集三视图 > 作品内实机截图或关键 CG > 授权衍生图」的优先级下载图片至 `_web/<角色>/`，直接读图记录可见特征：
  1. **发色与瞳色**：并列记录立绘受光面的具体观测色与百科信息栏的归类色（例如室内观感近黑、受光泛暗橄榄绿），兼顾准确度与日常光影感。
  2. **面部与体态**：发型分缕、刘海与发饰位置、眉眼走势、标志性神情、身高体型比例与站姿习惯。
  3. **服饰层次与随身器物**：由外及内的衣着形制、主副配色、材质纹理、袖口领口细节、鞋袜配饰及随身携带的器物。
  4. **遮挡与未展示部位留白**：画面裁切、衣摆遮挡或官方未公开的局部细节（如内衬、鞋底、暗袋物品），如实记为「立绘未展示」，留待下游按作品时代与人物性格开放设计。
- 同类信息栏出现实质冲突（如两处百科对发色或身高的记载相左）时，对比站点一手程度与更新时间并在判断栏写明取舍。

# PDB 人格数据与评论采集

获取条目直链后归档保存，后续直接请求直链或数据接口读取完整票型分布：

```
https://api.personality-database.com/api/v1/profile/<数字id>
```

- 通过 Chrome headless 配合持久化 profile 读取 JSON：`breakdown_systems` 提供 16 型、九型、本能副型、tritype、socionics 等各系统完整票数，`mbti_letter_stats` 提供四轴字母占比，`functions` 提供认知功能栏。
- 用四轴字母占比快速定位社区争论焦点轴；`profile_name_searchable` 可用于核对英文检索名；统计本能副型时将 `SX2` / `SO2` 类混合票与纯副型票合并同类计算，微小票差视作统计波动。

## 评论区与回复接口

票数反映社区共识结果，高赞长评与往返辩论提供认知功能拆解依据。在前端 bundle（`static2.personalitydatabase.net/pdb.<hash>.js`）确认接口结构后，在 `www.personality-database.com` 同源页面上下文内拉取顶层评论与子回复：

```
顶层：https://api.personality-database.com/api/v1/comments/<profile_id>?sort=NEW&offset=0&range=all&limit=50&version=W3
回复：https://api.personality-database.com/api/v1/comment_replies?comment_id=<comment_id>&limit=50&offset=0
```

- 按顶层评论返回的 `reply_count` 传入 `comment_id` 逐条拉取完整争论链；通过 CDP `Network.setUserAgentOverride` 设置 UA，轮询 `/json/version` 确认调试端口就绪；遇到残留锁文件占用 profile 时清理 `Singleton*` 或切换临时 profile。

## 判型分析要求

- 结合全量台词、关键剧情抉择与大样本投票综合推导：高样本量（如数十票以上且占比悬殊）的票型作为强参考，小样本票数结合原作言行独立核验。
- **判型交接写法**：MBTI 段结合具体认知功能（如 `Ni-Te`、`Fe-Ni`、`Si-Te`）与剧情行为写出主判型成立的证据，并点明与次高票备选型在信息收集或判断轴上的核心分歧；核心渴望、恐惧与防御机制归入九型与本能副型段，保持各类型学维度职责清晰。

# 搜索渠道调度

原生挂载搜索工具（`x_search` / `web_search` / `exa`）可用时直接并行调用：

| 需求场景 | 首选工具 | 调用要点 |
|---|---|---|
| 实时网页检索与综合核实 | MCP `web_search`（xai-search） | 带引用 URL 返回综合结果 |
| X/Twitter 官方账号动态与社区风向 | MCP `x_search`（xai-search） | 支持按账号 handle 与日期区间精确检索 |
| 语义检索与长文抓取 | MCP `exa` | 使用完整自然语言描述目标页面，配合 `additionalQueries` 多路扩展 |
| 已知 URL 提取干净正文 | Jina Reader：`curl.exe "https://r.jina.ai/<URL>"` | 20 RPM 免密钥输出 Markdown |
| 命令行特殊参数或脚本兜底 | `scripts/grok_search.py` | 支持 `--tool both`、指定模型与原始 `--json` 输出 |

- 涉及近期新作、新角色、连载更新或细节核实时，拆解原文名、中文名、英文名与「設定 / 世界観 / あらすじ / 性格 / 台詞」多路并行检索；官方一手材料与社区讨论分开标注归档。

## 深度搜索流程

用户要求「深搜」「深挖」「深度搜索」或指定高来源数量时：

1. **拆解子角度**：围绕主题拆出 3～6 个互补维度（多语种名称 × 官方设定 / 剧情实况 / 人物关系 / 名场面台词 / 社区考据）。
2. **首轮并行**：按用户指定的渠道偏好（默认 `exa` + `web_search` + `x_search` 并行；若用户指定单一渠道则按指定渠道拆多组查询）同步发出首轮检索。
3. **提取新实体**：从首轮结果提取新出现的关键事件、专名、地点与关联人物，生成第二轮递进查询。
4. **二轮追击与汇总**：针对新线索补搜，合并去重后统计有效来源数，区分官方实锤与粉丝考据写入调研分包。

## xai-search 参数与排障要点

- `x_search` 参数：`allowed_x_handles` / `excluded_x_handles`（单次上限 10 个，二选一）、`from_date` / `to_date`（`YYYY-MM-DD`）。
- `web_search` 参数：`allowed_domains` / `excluded_domains`（单次上限 5 个，二选一）。
- 脚本调用示例（读取环境变量 `XAI_API_KEY`，代理通过 `HTTPS_PROXY` 配置，REST 参数见 `references/xai-grok-api.md`）：

```bash
python "<技能目录>/scripts/grok_search.py" "查询问题" --tool x --from YYYY-MM-DD
```

- 环境兼容细节：Windows 命令行显式调用 `curl.exe`；Jina 正文提取使用免密钥的 `r.jina.ai`；Exa 的 `includeText` / `excludeText` 传入单元素数组。

# 检索核实准则

1. **区分抓取受阻与站点缺条目**：遇到 403、超时或空白响应时如实记录抓取受阻状态；确认某站未收录某角色前，先打开该作品在站内的分类或角色总表逐一核对（冷门或新作角色常挂在系列旧作或综合词条下）。
2. **同名消歧精确检索**：角色名与日常常见词重合时，组合「作品原名 + 角色原名 + `site:`」精准锁定目标页面。
3. **受阻及时交接**：同一站点尝试三种抓取路径仍受阻时，记录已尝试方式与目标链接，请作者直接提供页面文本或截图归档。
