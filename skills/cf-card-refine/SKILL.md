# 精炼卡文本

## 判断标准

每句话只问一件事：**删掉它，模型玩卡时写出的内容会不会变？**

- 不会变：删。
- 会变：保留，并改写成「条件 → 结果」，写明限度和例外。
- 数值、条件、阈值、限定、例外一条不丢。精炼是去掉不起作用的字，不是缩短篇幅。

精炼的结果是提案。改动列成 before → after 交作者确认；作者没确认的不写成定稿。

## 世界书条目：自定义 key

条目名本身就是 key；下一层用这个条目自己的方面名作 key，值写机制。

```yaml
# 示例（自写，按当前卡改写）
潮能:
  定义: 涨潮时在海水里积聚的能量，临海市的照明和船运都靠它。
  存在形式: 涨潮时积聚，退潮后三小时内散尽，不能长期储存。
  采集: 只有港口研究所的浮标阵能截留；私人截留按走私论处。
  过载: 单次接触超过一桶量会灼伤神经；研究员不得连续值两个潮次。
```

- **不套通用槽位。** `name / definition / description` 这类固定栏会逼出两种废话：把名字换个说法再说一遍的定义，和回顾往事的描述。方面名按条目实际情况起，每个条目可以不同。
- **定义只在需要时写。** 名字不足以说明它是什么、起什么作用时，用 `定义:` 写一句；只是复述名字的删掉。
- **方面写机制。** 一个方面回答一个问题：在什么条件下发生、发生后是什么、到什么程度为止、什么情况下不发生。
- **往事改成现状。** 只讲过去、对当下没有作用的删掉；仍影响当下的，改写成现在的规矩、禁忌或格局，放进对应方面。
- **评价词换成事实。** 「强大」「繁荣」「残酷」改成能观察到的结果；改不动就标【缺口】，不编。
- **系统条目不代写个体。** 某个角色对这条规则怎么感受、怎么应对，写进那个角色的设定。
- **同一事实只写一处。** 两个条目都写了同一个数值或范围时，保留一处，另一处删掉或只写引用的条目名；数值互相矛盾时标【缺口】交作者，不自行挑一个。
- **不需要展开的条目写成一行。** `条目名: 一句现状`。

### 写卡备忘不进正文

正文只写模型玩卡时要用的内容。写给写卡人自己看的取舍说明，模型看不懂它指的是什么，留在正文里只会占位置，还可能被当成设定。

常见的样子：`description_guide: 不用某某的推测`、`按第三卷的说法写`、`此处以官方设定为准`、`旧稿写错了，已改`、`待作者确认`。

- 这类句子挪到节点的 `## 工序` 段或 `note/`，不导出。
- 备忘背后的结论直接写进正文。例如资料里有人物猜测和后来揭晓的答案两种说法，正文只写揭晓的答案；不写「不用那个猜测」。
- 猜测本身对扮演有用时（这个人物会这样误判），写进说这话的人物自己的节点，标【角色说法】，不进世界条目。

```yaml
# 示例（自写）
# before：正文里留着写卡备忘
灯塔守则:
  description_guide: 不用镇长的说法，按守塔人日志写
  熄灯: 雾天不熄灯。

# after：备忘挪到 ## 工序，正文只留结论
灯塔守则:
  熄灯: 雾天整夜点灯；只有守塔人能熄灯，镇长无权下令。
```

## 角色设定：从上位概念往下收窄

顺序是 `上位概念 → 关键词 → tag → 具体细节`。每往下一层，模型越偏向这个方向，其他可能也越少。所以每一层都是作者的选择，不是 AI 按标签的常见联想自动补出来的。

```yaml
# 示例（自写）：同一个上位概念，不同的下位方向得到不同角色
互动风格:
  - 雌小鬼：发现别人说错话就抓住不放，用反问让对方自己承认
  - 雌小鬼：主动挑容易激怒对方的话题，看对方什么时候绷不住
  - 雌小鬼：只对认可的人挑衅，用来试探对方能接受自己到什么程度
```

写到能进正文时，写她注意什么、通常往哪个方向反应、有哪些变化：

```yaml
雌小鬼:
  解释: 互动里在意谁占上风；别人露出破绽时，往往拿来取乐。
  语言:
    - 常用反问指出对方刚说错的地方。
  行为:
    - 看对方的反应，决定继续挖苦、改成玩笑，还是先收住。
```

- **停在上位概念也可以。** 作者只想给范围时不往下写：`喜欢吃水果` 保留了开放性，改成 `夏天吃冰镇西瓜` 就锁定了方向。只有这个细节是角色辨识点时才往下写。
- **参照锚点。** 作者说不清细节、但知道想要的感觉时，可以写 `傲娇：像某作品某角色那样`。参照只提供方向，不搬原角色的经历、能力、口头禅和关系。之后从参照里挑出作者真正想留的部分，改写成这个角色自己的语言和行为。
- **不写固定流程。** 「每次犯错先反问三句再命令道歉」会被模型照做。改成方向加变化：「常抓住失误反问，按对方反应决定继续、改成玩笑或收住」。
- **近义标签合并。** 嚣张、顽劣、欺负人往往都在「雌小鬼」的范围里。每个标签都要带来新的语言、行为、选择或关系表现；带不来就合并。确实负责不同内容的，拆开写明各管什么，例如「雌小鬼管怎么挑衅、嘴硬管被反将一军时怎么回应、关系例外管对谁收着」。
- **写不出时只提问。** 作者只给了「喜欢画画」，就问最影响扮演的一个问题（喜欢画画本身还是画画时的安静？画给别人看吗？），一次问一个，或列成缺口。不替作者补一套背景。

## 每层自查

1. 这一层是作者想锁定的方向吗？
2. 有没有带来新的信息？
3. 是否属于上一级概念？
4. 有资料或作者的明确意图作依据吗？
5. 和别的标签重复吗？
6. 写成固定流程了吗？
7. 会不会挤掉作者想保留的其他可能？

有价值的细节会改变角色的语言、行为、选择、关系、场景反应，或者给正文提供可调用的素材。改变不了的，不管写得多具体都删。

## 交付

- 只列改动：位置、before → after、删改理由（落在上面哪一条）。
- 要作者决定的（锁不锁某个方向、矛盾数值取哪个、缺料怎么补）单独列出，不替作者定。
