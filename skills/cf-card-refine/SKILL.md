# 精炼卡文本

总规则：

- 每句话只问一件事：**删掉它，模型玩卡时写出的内容会不会变？** 不会变就删；会变就改写成「条件 → 结果」，写明限度和例外。
- 数值、条件、阈值、限定、例外一条不丢。精炼是去掉不起作用的字，不是缩短篇幅。
- 精炼结果是提案：改动列成 before → after 交作者确认，没确认的不写成定稿。

## 世界书条目

写法：

- 条目名作 key；下一层用条目自己的方面名作 key，值写机制。
- 不套 `name / definition / description` 固定栏。方面名按条目实际情况起，条目之间可以不同。
- 定义只在名字不足以说明它是什么、起什么作用时写一句；复述名字的删。
- 一个方面回答一个问题：什么条件下发生、发生后是什么、到什么程度为止、什么情况下不发生。
- 只讲过去、对当下没有作用的往事删掉；仍影响当下的改写成现在的规矩、禁忌或格局。
- 「强大」「繁荣」「残酷」换成能观察到的结果；换不动就标【缺口】，不编。
- 角色对规则的感受和应对写进角色自己的设定，不进系统条目。
- 同一事实只写一处；数值互相矛盾时标【缺口】交作者，不自行挑一个。
- 不需要展开的条目写成一行：`条目名: 一句现状`。

示例（自写，按当前卡改写）：

```yaml
晚钟:
  定义: 山间小镇每晚敲的钟，钟响后全镇进入夜禁。
  敲钟: 日落后一刻由守钟人敲九下；下雪天提前到日落时敲。
  夜禁: 钟响后不得出镇；镇内走动要提灯，不提灯的被巡夜人送回家。
  例外: 接生和送药的人可以出镇，出镇前要到钟楼登记。
```

## 写卡备忘不进正文

适用：正文里出现写给写卡人看的取舍说明。模型看不懂它指的是什么，留在正文里只会占位置，还可能被当成设定。

常见的样子：`description_guide: 不用某某的推测`、`按第三卷的说法写`、`以官方设定为准`、`旧稿写错了，已改`、`待作者确认`。

写法：

- 挪到节点的 `## 工序` 段或 `note/`，不导出。
- 备忘背后的结论直接写进正文：资料里有人物猜测和后来揭晓的答案时，正文只写答案，不写「不用那个猜测」。
- 猜测对扮演有用时（这个人物会这样误判），写进该人物自己的节点，标【角色说法】，不进世界条目。

示例（自写）：

```yaml
# before：正文里留着写卡备忘
晚钟:
  description_guide: 不用镇长的说法，按守钟人日志写
  敲钟: 下雪天不改时间。

# after：备忘挪到 ## 工序，正文只留结论
晚钟:
  敲钟: 下雪天提前到日落时敲；只有守钟人能改敲钟时间，镇长无权下令。
```

## 规则写上位，例子写下位

适用：跨角色生效的倾向、本能、风俗类条目。

写法：

- 条件和反应写上位：类别加关系维度（年长对年幼、指导者对被指导者、熟悉环境的一方对新来的一方），不写具体身份。上位写宽，模型才能套到没列出的组合。
- 例子写下位：具体身份、场景、动作。每个例子落在不同条件上，不重复同一种组合。例子示范怎么落地，不是照抄清单。
- 反应写倾向和强度（一丝、有点、会犹豫），写明只微调性格原本的决定，不取代性格；不写必然动作，结果留开放。
- 概念名只在条目里用；正文用自然语言时在条目里给一对错/对写法。这是写给模型的指令，不算写卡备忘。

示例（自写）：

```yaml
护短倾向:
  定义: 对自己负责照看的人会不自觉地偏袒；本人察觉不到，只微调性格原本的决定。
  条件:
    - 年长的一方对年幼的一方
    - 负责指导的一方对被指导的一方
    - 熟悉环境的一方对新来的一方
  反应:
    - 对方被外人指责时，先替对方找理由
    - 对方犯小错时，比平时宽容一点
  例子:
    - 高年级的学姐看到学弟被老师训，下课后去问他哪里没听懂。
    - 负责指导的女仆发现新人打碎了杯子，先把碎片收拾掉，再私下提醒。
  正文写法: 不写「她的护短倾向让她……」，写「她没多想，先把碎片扫进了簸箕」。
```

## 角色设定：从上位往下收窄

顺序：`上位概念 → 关键词 → tag → 具体细节`。每层收窄都是作者的选择，不按标签的常见联想自动补。

示例（自写）：同一个上位概念，不同的下位方向得到不同角色。

```yaml
互动风格:
  - 雌小鬼：发现别人说错话就抓住不放，用反问让对方自己承认
  - 雌小鬼：主动挑容易激怒对方的话题，看对方什么时候绷不住
  - 雌小鬼：只对认可的人挑衅，用来试探对方能接受自己到什么程度
```

写到能进正文时，写她注意什么、通常往哪个方向反应、有哪些变化：

```yaml
雌小鬼:
  解释: 互动里在意谁占上风；别人露出破绽时，往往拿来取乐。
  语言:
    - 常用反问指出对方刚说错的地方。
  行为:
    - 看对方的反应，决定继续挖苦、改成玩笑，还是先收住。
```

写法：

- **停在上位概念也可以。** 作者只想给范围时不往下写：`喜欢吃水果` 保留了开放性，改成 `夏天吃冰镇西瓜` 就锁定了方向。只有这个细节是角色辨识点时才往下写。
- **参照锚点。** 作者说不清细节、但知道想要的感觉时，可以写 `傲娇：像某作品某角色那样`。参照只提供方向，不搬原角色的经历、能力、口头禅和关系。之后从参照里挑出作者真正想留的部分，改写成这个角色自己的语言和行为。
- **不写固定流程。** 「每次犯错先反问三句再命令道歉」会被模型照做。改成方向加变化：「常抓住失误反问，按对方反应决定继续、改成玩笑或收住」。
- **近义标签合并。** 嚣张、顽劣、欺负人往往都在「雌小鬼」的范围里。每个标签都要带来新的语言、行为、选择或关系表现；带不来就合并。确实负责不同内容的，拆开写明各管什么，例如「雌小鬼管怎么挑衅、嘴硬管被反将一军时怎么回应、关系例外管对谁收着」。
- **写不出时只提问。** 作者只给了「喜欢画画」，就问最影响扮演的一个问题（喜欢画画本身还是画画时的安静？画给别人看吗？），一次问一个，或列成缺口。不替作者补一套背景。

## 每层自查

1. 这一层是作者想锁定的方向吗？
2. 有没有带来新的信息？
3. 是否属于上一级概念？
4. 有资料或作者的明确意图作依据吗？
5. 和别的标签重复吗？
6. 写成固定流程了吗？
7. 会不会挤掉作者想保留的其他可能？

有价值的细节会改变角色的语言、行为、选择、关系、场景反应，或给正文提供可调用的素材；改变不了的删掉。

## 交付

- 只列改动：位置、before → after、删改理由（落在上面哪一条）。
- 要作者决定的（锁不锁某个方向、矛盾数值取哪个、缺料怎么补）单独列出，不替作者定。
