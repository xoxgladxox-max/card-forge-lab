# 卡工程流程（v3.9.0）

范围：负责卡工程文件的落盘位置、目录分区、执行顺序与哈希核对。流程独立于具体命令行，工具调用示例见文末「工具对照」。

总规则：

- **每次立项、移动、重命名或同步前先写出明确判断并自检信息缺口**：在对话或 `记录\执行计划.md` 中写明该文件属于哪一类文本与物理分区（例如区分全场景泛化角色本体与独立条件绿灯语料/事件/亲密节点）、若放错区域或漏改联动字段会造成什么装配或触发事故；若遇到来源不明、归属有歧义的文件，先停下向作者提问确认归属后再落入正式分区。
- 卡工程是正式落档目录，所有正式节点均在卡工程内维护。
- 工作台草稿与酒馆侧产生分歧的改动先进 `候选\` 或 `待归位\`，由作者确认后再写入正式分区。
- 条目身份由名字与稳定 `id` 定位，版本同异由程序计算的正文哈希判定，条目数量以程序扫描结果为准。
- 推送、拉回、装卡前先生成备份。
- 机器返回成功代表结构与装配过检，内容确认由作者单独裁定。
- 标【待定】的事项按默认方案暂存，并在交付报告中集中列出供作者决定。

# 一、三类协作层

| 层级 | 是什么 | 职责 |
|---|---|---|
| 工作台 | 编辑器、AI 工具与配套流程 | 查资料、写判断、拟方案、改节点；作者确认前的阶段产物先存 `候选\` |
| 卡工程 | 单张卡的一级文件夹 | 保存全部正式节点、配套脚本与过程记录 |
| 同步工具 | 拆卡、装卡、推送、拉回程序 | 执行双向转换、哈希核对与备份 |

# 二、位置与命名

```
<卡工程根目录>\<卡名>\
```

- 每张卡独立为一个 `<卡工程根目录>\<卡名>\` 一级文件夹，`card.md` 直接放在 `<卡名>\` 根目录下，供同步面板与 `check` 定位卡根。
- 卡名取酒馆卡文件名去掉 `.png` 后的名称（例：`示例卡.png` → `示例卡`），推送与拉回按同名匹配酒馆内的卡。
- 旧原稿、小说母本、历史草稿等参考资料统一放入 `<卡名>/记录/`、`<卡名>/候选/` 或 `<卡名>/note/`，构建器扫描时自动跳过这些非装配目录。
- 酒馆里的卡改名时，卡工程文件夹同步改名，内部条目的 `id` 保持原值。
- 工程放在当前工作环境有写权限的路径下；遇到跨盘或连接点写入受阻时立即停下报告。
- 工程外部的参考资料保持原位只读，在记录中注明路径引用。
- 路径包含 `[` 或 `]` 时，PowerShell 命令统一使用 `-LiteralPath`。

# 三、物理分区

```
<卡名>\
  card.md                      卡根：卡名、世界书名与保留在卡根的扩展设置
  <字段>.md                    顶层单槽字段：description.md、system_prompt.md 等纯正文文件
  message\0.md                 开场白：0.md 装入 first_mes，1.md 起按序号装入 alternate_greetings
  lorebooks\**\<条目>.md       世界书条目：兼容旧目录名 world_book\，可按 world / character / style / output 建子目录分组
  regex\<序号>-<名>.json+.html 卡内正则：设置文件与非空替换模板，含隐藏标签块的双通道剥离脚本
  scripts\<序号>-<名>.json+.js 酒馆助手脚本、variables.json、xiaobaix-tasks.json、xiaobaix-template.json+.html、xiaobaix-variables.json
  character.png                封面图
  前端源码\                    前端可读源码、美术原图与离线预览页，打包产物输出至 scripts\ 与 regex\
  记录\                        执行计划.md、决策记录.md、审查报告.md、调研\ 分包目录、已归档计划\、核对记录
  候选\                        待作者确认的草稿与多版本比对稿，按 候选\<条目名>\<来源>.md 归档
  待归位\                      拉回时酒馆侧产生冲突或新增的待处理条目
  backups\                     推送、拉回、装卡前的自动备份
  dist\                        装卡输出的 JSON / PNG 成品
```

- 装配进卡的文件集合为：`card.md`、顶层单槽字段 `.md`、`message\<n>.md`、`lorebooks\**\*.md`（兼容 `world_book\**\*.md`）、`regex\`、`scripts\`、`character.png`。
- 文字版与前端版并存时，在根目录下建立两个并排的独立 `<卡名>\` 文件夹，各自对应同名酒馆 PNG 与独立世界书名称。
- 每条世界书条目对应一个 `.md` 文件；子目录承担分类导航职责，注入位置与触发属性由文件头 YAML 控制。

|---|---|---|---|---|

| **1. 进卡源区** | 角色泛化设定区 | `lorebooks\character\<角色>.md`、`*阶段*.md` | 全场景泛化规律说明文体（零原句台词、零单次事件） | 装入 `character_book` 人物泛化设定号段 |
| **1. 进卡源区** | 角色条件语料与事件区 | `lorebooks\character\<角色>语料.md`、`*过往事件.md`、`*亲密表现.md` | 条件绿灯口语样本、往事经过与亲密反应采样（附校准说明） | 以独立条件绿灯（`constant: false`）装入 `character_book` |
| **1. 进卡源区** | 文风说明区 | `lorebooks\style\*.md` | 镜头与描写说明文体 + 采样短段 | 装入 `character_book` 文风号段 |

| **1. 进卡源区** | 正则与脚本产物区 | `regex\`、`scripts\` | 正则配置（含隐藏标签块双通道剥离脚本）、前端打包任务与变量 | 装入 `data.extensions` 对应槽位 |
| **2. 前端源码区** | 前端开发与素材区 | `前端源码/terminal.src.js`、`assets/`、`preview.html` | 可读前端源码、原图素材与离线预览页 | 留在工程内维护，经打包脚本生成 `scripts\` / `regex\` 产物 |

| **3. 过程记录区** | 调研分包区 | `记录\调研\{00-索引, world-*, rules-*, char-<角色>-档案与判型, char-<角色>-台词语料}.md` | 客观事实、专业判型分析与原话摘录分包 | 留在工程内供对应写作阶段按需单读 |

## 多开局、思维链正则与改名全书同步约定

1. **多开局配对归档**：
   - `message\0.md`、`message\1.md`... 按开局序号存放各开场白纯正文，初始 `<status>` 保持表面可观测穿戴与暗袋泛用词留白。
   - 多开局共享的主角核心能力或基础设定归一为一条开放式常驻主角节点（兼容不同来历与流派，移除固定自动应对公式）；若各开局存在专属情境分支或前端初始变量表（如 `INIT[0]`、`INIT[1]`），按相同序号在 `记录\决策记录.md`、条件触发条目与初始化脚本中对齐。
2. **隐藏标签块剥离正则配对归档**：
   - 当 `description.md`、`system_prompt.md`、`output` 节点或开场白中包含要求模型输出但不给读者看的隐藏标签块（如 `<thinking>`、正文 `<state>` 等）时，同步在 `regex\` 下按配套规范逐一归档对应的双通道剥离脚本（开启显示与提示词双通道剥离，一种标签对应一条脚本文件），避免未剥离的内部块残留进界面或后续上下文。
3. **条目改名与扩容全书同步**：
   - 重命名世界书条目时，同一轮联动更新：`.md` 文件名（可保留 `01-`、`08b-` 等排序前缀）、YAML 头部 `title:`、正文首行 `<标签 name="...">` 以及 `记录\执行计划.md` 中的路径引用。
   - 常驻蓝灯（`constant: true`）改名或调整统领范围时，同步核对 `prevent_recursion: true` / `exclude_recursion: true` 设置与三明治分组目录；下位绿灯条目改名、拆分或新增专名时，同步更新其 `keys` 触发词，并全书检索 `description.md` 与所有常驻蓝灯正文，将新出现的下位专名替换为上位泛用词，确保 `[P18f]` 与 `[P25]` 零泄漏。

工程管理按三个独立单元（Unit）分步推进：
- **Unit 1 建仓与盘点**：扫描或拆出目录，写出分区归属判断，将非标准文件归入 `待归位\` 或 `候选\`，输出归位清单后**停下等作者确认**。
- **Unit 2 立项建单**：在 `记录\执行计划.md` 把本轮工作拆成带「前置判断、目标模块、只读分包、只写路径、文本类型」的独立子项后**停下等作者确认**。
- **Unit 3 完结归档与同步**：全部子项完成后，归档计划至 `记录\已归档计划\`，提炼长期结论入 `记录\决策记录.md`，执行 `check` / `build` 校验与酒馆推送或拉回。

## `.md` 节点文件的两类结构

### 格式 A：带 YAML 头部的节点文件（`card.md`、`lorebooks\**\*.md`）
文件开头使用 `--- ... ---` 标准 YAML Frontmatter 声明装配属性；`card.md` 保存卡级元信息，`lorebooks\**\*.md` 在第二个 `---` 下方紧接装入世界书的正文（同时向下兼容含 `<!-- body -->` 分隔标记的旧版节点文件）：

```markdown
---
id: wb-character-201
type: character
title: "角色名"
keys: [角色本名, 简称]
position: before_char
constant: false
order: 201
---

<character name="角色名">
...
</character>
```

- `position` 取值：`before_char`、`after_char`、`"@D0"` / `"@D1"` / `"@D2"` ...（带 `@` 的深度值在 YAML 中加双引号）。
- `type` 取值：`card`、`world`、`location`、`rule`、`item`、`lore`、`character`、`module`、`corpus`、`style`、`output`、`greeting`、`note`、`plot`、`wiki`、`event`。
- 常驻条目设 `constant: true`，并默认开启 `prevent_recursion: true` 与 `exclude_recursion: true`；触发条目设 `constant: false` 并填写非空数组 `keys: [...]`。按需配置 `enabled`、`secondary`、`selectiveLogic`、`scan_depth`、`probability`、`ignore_budget`。

### 格式 B：纯正文单槽文件（顶层单槽字段与开场白）
- 适用文件：`description.md`、`personality.md`、`scenario.md`、`mes_example.md`、`system_prompt.md`、`post_history_instructions.md`、`message\0.md`、`message\1.md`...
- 全文直接作为对应槽位的纯正文装入。

# 四、认文件与认版本

| 核对目标 | 判定依据 |
|---|---|
| 定位同一条目 | 名字与稳定 `id`（如 `wb-2`，改名时保持 `id` 恒定） |
| 判定内容同异 | 程序对纯正文计算的 SHA-256 哈希 |
| 查看具体改动 | 哈希不同时查看程序输出的差异行 |
| 核对条目总数 | 程序扫描统计的数字 |

- 同名条目仍须逐条比对正文哈希，确认内容一致。
- 比对前先核验程序提取的正文切片，确认已剥离头部 YAML 设置与旧版工序说明块。
- 读取长文件时记录起止行号与总行数，按页续读直至完整覆盖全文。
- 两侧存在差异时，并列标注双方修改时间与差异摘要交作者选择。

# 五、操作流程

## A. 接卡：酒馆里的卡 → 卡工程

1. 定位原卡：在酒馆数据目录 `characters\` 下确认目标 PNG，或通过同步工具列出当前卡。
2. 准备目标路径：保持 `<卡工程根目录>\<卡名>\` 未创建或为空目录，交拆卡工具生成初始工程。
3. 执行拆卡：拆卡前后分别计算原卡文件哈希，确认原卡字节未变。
4. 装回核对：运行装卡工具生成成品，按条目 `id` 逐字段比对原卡与成品；发现正文、触发设置或扩展脚本存在差异时立即停下报告。以下两类属于宿主运行态差异，豁免报错：
   - 卡外层的 `avatar`、`chat`、`create_date`、`creatorcomment`、`fav`、`tags`、`talkativeness`：由酒馆维护，推送时酒馆自动保留。
   - 世界书条目在数组中的物理排布顺序：酒馆运行时按 `order` 与 `display_index` 排序。
5. 核对独立世界书（如绑定 `worlds\<世界书名>.json`）：逐条核对正文、触发词、`order`、常驻、启用、位置与深度。
6. 建立 `记录\` 与 `候选\`，将核对结果写入 `记录\接卡核对.md`。

## B. 对应旧版（存在历史工程时）

1. 程序剥离旧版说明块后计算纯正文哈希，将新拆条目与旧版逐一配对。
2. 输出对应表至 `记录\对应表.md`，按三类归档：
   - 哈希相同：采用新拆正文，沿用旧版的类型、命名及来源记录。
   - 哈希不同：正式区保留新拆版本，旧版本存入 `候选\<条目名>\`，并列双方修改时间交作者决定。
   - 仅旧版存在：整份存入 `候选\<条目名>\旧节点.md` 并标注来源。
3. 按命名同步规则一次性对齐文件名、`title:` 与顶层标签，原旧版目录保持只读留档。

## C. 新建卡工程

1. 需要同步酒馆时，先在酒馆内建立同名空白角色占位。
2. 创建 `<卡工程根目录>\<卡名>\` 与 `card.md`。
3. 按 `记录\执行计划.md` 分单元写入各分区节点。

## C2. 旧版节点树迁移或散乱草稿整理

遇到旧版节点树（含根 `index.md` 或 `world\`、`character\` 等目录下的 `<节点>\index.md`）或无头部的散乱设定草稿时，先在工作台整理为第三节的标准分区结构：

- 旧版节点树：运行 `migrate` 迁移至全新空目录，保留原目录只读；原样搬运正文、工序记录与已有 `id`、`order`、触发参数；将调研、决策记录、`note\`、`archive\` 等归入 `记录\`；待解析项归入 `待归位\`，去处冲突项归入 `候选\`。
- 散乱草稿：先写出各段落的文本类型判断与分区归位提案（哪段进单槽字段、拆成哪几条世界书），经作者确认后落盘；暂未定夺的段落归入 `待归位\`。

整理完成后：

1. 核对迁移报告中的【缺口】与参照成品差异并呈报作者。
2. 执行 `build` 并与参照成品做哈希比对，有差异则停下报告。
3. 对齐酒馆卡名后按 E 节流程推送。

## D. 日常修改与执行计划

`记录\决策记录.md` 保存长期生效的最终决定（结论 + 来源）。日常多步制卡或修改通过 `记录\执行计划.md` 管理：

1. **先写判断与执行计划落盘**：动手前在 `<卡名>\记录\执行计划.md` 写明本轮诊断判断、修改范围、分步勾选清单（`- [ ]` / `- [~]` / `- [x]`）、待确认项与已确认前提。
2. **按文本类型分包单读**：资料与节点按模块存放（如 `记录\调研\world-*.md`、`rules-*.md`、`char-<角色>-档案与判型.md`、`char-<角色>-台词语料.md` 及对应 `lorebooks\` 子目录）。当前步骤处理哪一模块，就精准读取 `记录\执行计划.md` 与该模块的对应分包。
3. **执行期间实时同步**：每完成一步或收到新指令，先更新 `记录\执行计划.md` 进度，再修改目标节点；跨轮续接时先读该计划对齐状态。
4. **校验与确认**：分歧方案存 `候选\`，确认后写入正式区；涉及改名或扩容时跑完 `check`（含 `[P18f]`、`[P25]`）与 `build` 核对。
5. **完结归档**：提炼长期有效的结论补入 `记录\决策记录.md`，将当轮 `记录\执行计划.md` 移入 `记录\已归档计划\<日期>-<主题>.md`。

## E. 推到酒馆

- 推送前向作者列出目标卡名与本次变更条目清单，获得同意后执行。
- 确认酒馆处于运行状态，推送前自动或手动备份至 `backups\`。
- 若检测到酒馆侧存在未拉回的新改动，先执行拉回演练交作者确认，保留双方改动记录。

## F. 从酒馆拉回

- 先加 `--dry-run` 演练查看变更清单，确认后再正式拉回。
- 仅酒馆侧修改的条目：备份后直接更新卡工程对应文件。
- 双侧同时修改或酒馆新增未配对条目：写入 `待归位\` 隔离保存，待合入正式文件后移除对应 `待归位\` 项。

# 六、世界书编号（`order`）

世界书按类型分五组号段：世界 `1xx`（`world` / `location` / `lore` / `rule` / `item`）、人物 `2xx`（`character` / `module` / `corpus`）、文风 `3xx`（`style`）、输出 `4xx`（`output`）、其余 `5xx`（`plot` / `event` / `wiki` / `greeting`；单组超 99 条时自动升为四位 `1001` 起）：

- **新建卡工程**：省略手写 `order` 交由构建器按组与目录树自动连续编号，或在同一组号段内按顺序递增手写（支持 `201, 210, 220` 这类预留插槽的间隔递增写法）。
- **接来的外部卡**：原样保留原卡已有的 `order` 数值，保证装回比对零差异；后续新增条目接在同类号段之后递增编号。

# 七、停下报告的触发条件

遇到以下任一情形时立即停下，报告所在步骤、实际观测结果、已完成动作与待作者决定的事项：

- 装回核对出现正文、触发设置或扩展数据差异。
- 原卡文件哈希在拆卡前后发生变化。
- 目标路径无写入权限。
- 同一条目存在多份冲突版本待选定。
- 准备推送至酒馆但尚未获得作者同意。
- 作者发出停止或先纠正的指令。

# 八、交付报告

按实际执行的命令与程序输出如实列出：

- 卡工程完整路径与当前前置判断摘要。
- 核对方式、比对范围与差异数量。
- `候选\` 与 `待归位\` 中的待处理项数。
- 备份路径、成品输出路径及酒馆同步状态。
